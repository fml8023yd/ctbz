# 九步推荐流程 v1

本预设可选，不是强制绑定。用户可整套采用、逐项替换或不采用。明确说“草台班子 采用推荐流程”或在推荐后答“采用”即可使用本包方法，不运行 setup-matt-pocock-skills，不要求全局安装同名技能；已有自选方案优先。仅查看或选择流程而没有任务时不创建记录、不执行任务。免配置不等于快速模式、自动模式、模型初始化或发布授权。

S = Superpowers 已内置无需另绑；M = Matt Pocock 组，本包适配直接读取；官 = 官方插件，按需使用且不随包分发。

| 环节 | 推荐方法 | 执行及交付 |
| --- | --- | --- |
| ① 访谈 | grilling（M） | 父会话访谈；子 Agent 仅事实调查，输出需求、裁决和待决项 |
| ② 裁决落档 | domain-modeling 裁决/ADR（M） | 父会话执行；咨询设计目录，未指定则 ./docs/design |
| ③ 统一设计稿 | brainstorming（S）；ubiquitous-language 按需、design-an-interface 仅关键接口实质分歧时（M） | 父会话统稿，可收局部方案；原型前定验证问题、方法和通过标准 |
| ④ 原型验证 | CTBZ 完整链路原型；verification-before-completion（S）；prototype 仅逻辑/UI 辅助（M）；web-gui-tester 按需（官） | 隔离构建，执行者提供真实证据，不能以 mock/截图代替集成 |
| ⑤ 双层确认 | verification-before-completion 主导，requesting-code-review 按风险，receiving-code-review 处理反馈（S） | 父会话技术复核，用户明确确认业务效果；两层通过才继续 |
| ⑥ 回补定稿 | brainstorming + writing-plans（S）；domain-modeling 按需（M） | 父会话更新唯一设计稿、正式验收条件与实施方案 |
| ⑦ 任务拆分 | writing-plans + dispatching-parallel-agents + using-git-worktrees（S） | 父会话定稿，planner 可回草稿；依赖/write-set/接口/基线/验收齐全，交接新会话 |
| ⑧ 独立 worktree 开发 | subagent-driven-development + using-git-worktrees + test-driven-development + dispatching-parallel-agents（S） | 父会话唯一调度，执行者限定工作区；模块测试、评审及修复 |
| ⑨ 集成验收 | verification-before-completion + finishing-a-development-branch，requesting-code-review 按风险（S）；Web 沿用 web-gui-tester（官） | 父会话对集成版本完整链路、回归及最终交付负责 |

## 方法读取与用户选择

S 从 [方法索引](../methods/index.json) 获取入口。M 从 [Matt 适配方法](../methods/matt/recommended.md) 按阶段读取；不依赖宿主递归发现子技能，不在运行时解包源归档。ask-matt 只作来源与路由参考，不覆盖九步顺序。

to-spec、qa 不默认使用，to-tickets 不默认绑定；grill-with-docs 不替代 grilling。用户说“不用 prototype”只关闭该辅助技能，不取消完整链路验收。自选技能需核对实际入口和约束，不自动安装；缺失时说明，允许继续无依赖工作。

web-gui-tester 属官方插件，不在本包免配置闭包内。宿主可用时遵循其技能及浏览器工具规则；不可用时说明缺口，由用户选择安装或提供人工验证证据。不得伪称 GUI 通过，必要验证缺证据时不能通过验收。团队派发仍需合法初始化，父会话路径不依赖模型团队配置。

## ①—⑦的 Agent 分工

高能力主会话主持设计并唯一调度，不必在设计中途另设调度会话。对可独立验收的调查、设计草稿、文档整理、原型构建、测试和任务细化，优先交给能力匹配的 Agent；主会话负责裁决、审定和必要复核，而不是亲手执行全部步骤。表中的“父会话执行/更新/定稿”表示最终责任，不要求其独自生产全部材料。

| 环节 | Agent 承担 | 主会话保留 |
| --- | --- | --- |
| ① | 查代码、资料、现状和约束，验证事实、整理问题依据 | 主持访谈，决定问题顺序，向用户提出关键取舍 |
| ② | 依明确回答整理裁决/ADR，查遗漏矛盾，授权执行角色在指定范围落档 | 核对用户决定的忠实表达，裁定歧义 |
| ③ | 模块方案、接口/数据设计、词汇表、验证清单及独立复核 | 整体架构、跨模块边界、方案冲突及关键验证标准 |
| ④ | 隔离原型、真实链路及异常/边界测试、证据整理、明确缺陷修复 | 判断验证是否回答设计问题，处理关键假设失败 |
| ⑤ | 核查版本和证据、复现疑点、整理限制 | 技术复核最终结论；业务效果由用户确认 |
| ⑥ | 按证据更新设计、ADR、验收及实施方案，检查一致性 | 审核实质变化，判断是否须用户重新确认 |
| ⑦ | 细化任务/依赖/write-set/验证命令，检查冲突，整理交接包 | 审核边界、共享契约、需求覆盖及并行可行性 |

所有委派仅使用草台班子已配置、已激活且宿主已加载的 Agent 团队。主会话决定任务角色，逐次通过现有 initialize select 及团队调用规则选择具体 profile 和模型；不另组临时团队、不硬编码模型、不用通用 Agent 替代团队角色。团队未初始化、未激活或无合法候选时明确报告派发阻塞，不擅自替代；仅原协议允许的主会话工作可继续。简单整理和明确执行优先经济模型，复杂设计和高风险复核使用能力匹配的模型；经济性只在合法候选与既有选择规则内考虑，不一律选最便宜，不擅自更换 provider。每次派发传同一权威版本、输入材料、写集合、输出要求和验收条件。原型/测试须有实际输出，设计结论须有依据；关键或高风险成果按风险独立复核。主会话检查关键证据、缺口和矛盾，不只听摘要，也不重做全部工作。

业务歧义、跨模块冲突、关键假设失败和验收条件变化回主会话裁决；普通缺陷及明确范围内修复由 Agent 完成后交回证据，不因其称 DONE 就通过。微小机械动作可由主会话直接处理，避免派发开销超过收益，不为凑并行创建任务。

文档生产与裁决权分离：只读 planner/reviewer/reporter 返回草稿或发现，不因此获得写权限；需要落档时由已有写权限的执行角色按主会话明确授权、指定路径与写集合完成。只能转录有来源的用户确认，不把建议升级为已确认，不自行修改共享裁决。未审定草稿与权威版本明确区分，主会话审定后记录生效版本；项目状态、manifest、调度和确认状态仍由主会话统一管理。并行文档写任务同样遵循工作区隔离和唯一 owner。

⑦完成后仍提醒用户另开独立会话，以经济模型安排⑧开发调度；不是让设计 Agent 派生调度者，也不降低开发验收标准。

## 材料、门禁与交接

- 传递同一权威版本的绝对材料路径、必要背景、具体问题和约束。只读 Agent 返回事实或草稿，授权执行角色可生产文档，父会话审定；不得另建权威主记录。
- 设计目录先咨询，默认 ./docs/design，已有选择不重复询问。设计稿、ADR、计划及交接可保存在选定目录，执行 manifest、看板和过程证据仍在 .ctbz-record，引用设计而不复制第二份真值。纯讨论不写记录。
- ③覆盖目标与非目标、流程、接口、数据、状态、权限、异常、旧规则替代、关键假设与事实缺口。④独立目录构建，不改生产代码；至少一条真实完整核心链路跑通，阻塞实现的高风险假设均有证据，其余未验证项进入正式验收；纯后端不强制 UI。
- ⑤两层确认绑定同一原型版本，记录用户确认及范围。沉默、等待、截图、技术通过均不等于用户业务确认。任一层不通过回到设计/④重验。
- ⑥记录原设计、证据、调整与影响，明确原型代码保留/重构/替换；保留部分也需正式测试。业务行为、范围或体验变化交用户确认并重验受影响链路。
- ⑦只拆分，不创建 worktree 或派发开发。共享接口/schema/config 唯一 owner，冲突任务串行。完成后提醒用户另开独立会话安排开发，建议经济优先而不减验收、不擅自换模型。当前规划会话不自动进入⑧；用户明确改为同会话继续时尊重该选择，泛称自动模式不自动取消交接。
- 交接包含预设 v1 和覆盖项、项目/设计目录、设计/验收/任务计划绝对路径及版本、用户决定、依赖/write-set/基线、未解决项；提醒新会话核对材料和合法角色，不重问已确认决定，不承诺自动创建会话。
- ⑧并行写任务独立 worktree/分支，从确认基线开始，依赖成果就绪后对齐；模块通过不证明整体通过。⑨在实际集成版本运行核心链路、接口/数据/异常回归、原型遗留项及适用的部署升级检查。
- 不自动 commit、push、发布或清理。dirty/未集成工作区保留；删除按原授权协议。采用本预设不授权反审或真实计费探测。

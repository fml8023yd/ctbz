# 统一工作流与模式

本文件统一规定模式、询问与反审；旧条款冲突时以本文件为准。模式只改变同一流程的步骤，不另建流程。用户当前明确要求优先。

## 主路径

蓝图与验收标准 → 详细计划 → 计划反审 → 方案裁决 → 模块执行与自检 → 模块独立反审 → 集成反审 → 实际使用 → 蓝图验收 → 交付。

主进程保存原始需求、用途、不变条件、验收标准与未确定事实。计划包含模块、输入、接口、write-set、依赖、验证与完成条件。蓝图独立于实施计划，不通过修改目标使结果通过。

## 三种模式

| 模式 | 反审 | 询问与裁决 |
| --- | --- | --- |
| 普通 | 完整执行 | 明确默认方案后询问；回复优先，无回复满 30 分钟按默认继续 |
| 快速 | 可跳过独立反审 | 与普通一致；保留必要自检、实际验证、蓝图核对 |
| 自动 | 完整执行 | 主进程裁决并记录依据；不询问、不等待用户，不强制另开会话 |

未指定模式即普通。任务简单不自动跳过反审或方案裁决。已有明确裁决和仍有效授权不重复询问。【执行吧】【开始执行】只授权继续，不豁免反审。快速与自动可组合：跳过反审且不询问。

## 30 分钟默认

setting.yaml 的 权限边界.计划超时自动执行 默认 30（分钟），0 为用户显式关闭。倒计时适用于待答问题，不能仅因提出计划就启动。

问题必须同时给出默认选择或完整默认计划、适用范围、影响及到期时间。记录 questionId、askedAt、deadline、默认方案版本、范围、状态。每题从实际提出时起算；补充或修改该题默认方案后重新起算。收到相关回复立即取消该题倒计时并按回复处理；指代不明时暂停受影响问题，不把回复当作无回复。暂停或停止后不得到期续跑。

到期仅在当前授权范围内采用默认方案；缺少必需事实、无法自行取得的凭据、未授权外部操作保持阻塞，继续其他工作。沉默不能升级为权限授权。自动模式直接裁决，无需启动倒计时。

计时由父会话在真实检查点处理；宿主支持唤醒时可按其工具登记。配置本身不创建后台计时器，父会话退出不能保证准点执行。恢复时核对新消息、问题状态和版本后补执行，记录实际延迟。推送不是计时生效前提，不自动发送外部通知。

## 独立反审

普通与自动每个反审关口至少 3 名独立审查者；复杂计划沿用更高人数要求，可分批并发。不得因任务简单或 Token 成本自行缩减。团队不可用时标记反审阻塞，不以主进程自审冒充通过。

计划反审覆盖目标范围、可执行性、接口依赖、反例与验证；模块反审覆盖契约、边界反例、实现与测试；集成反审覆盖接口、完整链路、异常与回归；最终蓝图验收覆盖原始目标、实际使用和证据缺口。可合并角色视角，不减少覆盖。

审查材料包含原始需求、已确认蓝图、事实来源、当前计划或产物快照、验证输出与检查问题。首轮相互不看意见；不能只给实现者的摘要。每项意见给出位置、触发条件、证据、影响。主进程逐条接受、举证驳回或标记缺证据，不按票数盖过严重反例。执行者自检不能替代独立审查。

## 回修与交付

模块错误返回模块执行；接口错误返回接口与集成；计划不能达成蓝图返回规划；目标理解错误返回原始需求核对。保留仍有效成果，重审受影响部分。修复后的关键问题由新鲜审查者复核，旧快照通过不覆盖新版本。

每轮记录缺陷、修正与新增证据。连续两轮无新增证据，换诊断路径；无法继续则如实阻塞，不降低验收标准。最终交付必须满足模块成立、整体跑通、实际可用、蓝图达成；快速产出明确未做的独立反审。

## 实现边界

本规范由父会话执行。现有 team-state 仍只校验评审状态和非空证据；人数、独立回执、缺陷关闭和快照绑定尚非 CLI 强制校验。不得声称这些程序门禁已实现。

# 初始化、本机文件与规则

默认状态根为用户 Documents/.ctbz：macOS `~/Documents/.ctbz`；Windows 优先 `%OneDrive%/Documents/.ctbz`，否则 `%USERPROFILE%/Documents/.ctbz`；Linux 优先 `$XDG_DOCUMENTS_DIR/.ctbz`，否则 `~/Documents/.ctbz`。用户也可选择绝对自定义目录，程序仍在该目录内创建 `.ctbz`。选择later时不创建状态根，父会话仍可处理主会话任务；需要子Agent前再选择。该目录不进入发布包。profile目标默认~/.zcode/agents，可用--agents覆盖。所有路径参数用绝对路径。

## 命令

```text
node <skill>/scripts/initialize status
node <skill>/scripts/initialize prepare --storage documents --session <当前ID> [--config <宿主配置绝对路径>] [--selection <模型key数组JSON文件绝对路径>] [--agents <目标目录>]
node <skill>/scripts/initialize activate --session <新会话ID> --loaded <当前宿主profile名称数组JSON文件绝对路径> [--config <宿主配置绝对路径>]
node <skill>/scripts/initialize select --session <当前ID> --role reviewer --parent-model <custom:provider:model> --loaded <宿主列表JSON文件绝对路径> [--excluded <失败profile数组JSON文件绝对路径>]
node <skill>/scripts/initialize reload
```

首次 prepare 用 `--storage documents` 或 `--storage <绝对父目录>` 选择状态位置；成功后写本机 `~/.ctbz-location.json`，后续省略目录参数自动续接。各命令支持 `--home <绝对状态根>`，仅覆盖当前命令，不改本机选择。`status --storage later` 只查询“不选择”状态，不创建或清除已有记录。status 全程只读。

selection、loaded、excluded、catalog 均为 JSON 文件的绝对路径，不接受直接传数组文本。prepare 支持 --catalog 安全发现输出供离线检查，但真正 activate 须指向宿主配置。未给 selection 时使用发现的所有候选，父会话执行前展示数量并沿用已有生成授权；推荐显式选定模型。

同一角色每模型只生成一个最高受支持档位profile；无档位不发参数。已知顺序为 `off < none < minimal < low < medium < high < xhigh < max`，包含 `off` 无需手工补字段；未知排序仍需宿主确认 highestReasoning，不能猜最高档。

1.5.1 保留 discover-config 的原始候选 key，生成 profile 时只编码 provider 段的冒号。例如 `custom:builtin:bigmodel-coding-plan:GLM-5.3` 自动变为 `custom:builtin%3Abigmodel-coding-plan:GLM-5.3`；UUID 渠道与模型 ID 保持原样。selection、调用规则及 --parent-model 接受两种引用，已有 `%3A` 不重复编码。同一选择或顺序内的裸/编码别名视为重复，拒绝生成重复配置。激活时仍核对该模型的档位和真实 provider 的凭据声明。

候选带 providerId/modelId 时同时核对结构化身份，模型 ID 自身含裸冒号仍不支持并明确拒绝，不会把它误拆入渠道名。

路径参数仍拒绝文件或任意父目录为符号链接，包括 macOS `/tmp`。报错列出参数、输入路径、命中链接段与可解析的真实路径；确认后用真实绝对路径重试，不会自动放行。悬空链接会明确提示无法解析。

升级时重新 prepare，并在新会话检查实际加载后 activate。曾手工编码 key 或补 highestReasoning 的旧 catalog 需重新发现；建议直接用 --config。旧 selection 可保留。catalog 原始指纹必须和激活时现场发现一致，本版不把经过手工修改的 catalog 自动视为现场配置。

## 本机文件

- 调用规则.json：用户规则，首次为空活动集合，升级和初始化不覆盖。
- 初始化状态.json：版本、角色哈希、生成profile、配置位置与激活会话。
- 已初始化.txt：激活检查通过的时间，不是独立可信证明。
- generations/：每次变更生成的团队配置、setup与激活状态、旧profile备份。

prepare 在角色、profile、catalog 指纹和目标文件均一致时不重写；变更生成后需新会话激活。减少模型时，仅把内容仍匹配旧受管记录的退役 profile 备份到新 generation 的 backup/retired 并移出加载目录。自定义内容冲突时拒绝；正常异常回滚 profiles、旧状态、规则和标记。强制终止留下初始化.lock，需检查现场与备份后恢复，不盲删锁。文件备份不等于自动进程崩溃恢复。

## 规则

初始内容：

```json
{"schemaVersion":1,"default":{"sameProviderOnly":true,"modelOrder":[]},"temporaryRules":[]}
```

用户以后添加活动时，temporaryRules每项包含id、enabled、priority（小值先）、start/end（ISO时间带时区）、modelOrder（精确模型引用），可选roles。活动在[start,end)生效，可跨渠道；无活动可用候选时按同渠道默认顺序回退。过期规则保留但不参与。默认modelOrder只调整同渠道顺序，不能打开隐式跨渠道回退。

select每次读磁盘，输出rulesHash；reload显式重新校验。无需判断上下文是否缓存，文件始终权威。格式错误拒绝；规则引用未初始化模型拒绝，不猜profile。

## 运行衔接

生成 team-ctbz-*，复用原配置校验、模板、doctor 与 team-state。initialize status 是本版机器初始化状态入口；旧 scripts/status 的零参数默认位置不适用于新 generation。select 返回 stateDir 和 team，后续 init-run 显式传这些参数及 --workspace 项目目录；项目执行进度读取 dashboard show。磁盘就绪、宿主加载和真实模型健康是三件事；activate 只证明前两者及配置凭据声明，不证明 API 真实可用。真实 Agent 冒烟需具备相应调用授权。

prepare 在新旧 bundle 的 profile 名称集合一致时自动携带已激活会话（状态文件与 team-state 同步标记 `carried-from:<旧generation state>`），维护批次不再把正在使用的会话踢出激活列表；名称集合变化（增删模型）时不携带，按原流程要求新会话激活。旧 generation 悬挂的 run 用 `team-state adopt-run --state-dir <旧代state> --adopter-state-dir <当前state>` 跨代接管：权限按当前代会话校验，旧 manifest 冻结为 cancelled 并注明去向，续跑 manifest 重绑到当前代并记录 adoptions 溯源；终态 run 不可再接管。

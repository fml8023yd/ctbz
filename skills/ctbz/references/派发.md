# 派发（dsh 版规格）

父会话是唯一调度者。本文件是派发层的字段契约：角色规格如何落进 dsh 的三条派发通道，选型器如何产出 provider/model，健康账本如何记账。

## 1. 三条派发通道与字段映射限制（核心约束）

| 通道 | 用途 | 消费的字段 | 不消费的字段 |
|---|---|---|---|
| `workflow` 的 `agent(prompt, opts)` | 反审与讨论类扇出（多路并行、结构化回传） | 仅 `opts.provider`、`opts.model`（另有 `opts.schema`） | `persona`、`toolFilter`、`agentOptions` 一概不识别，静默丢弃 |
| `subagent` 工具实例 | 有界委派（一次性独立任务） | persona 文本、toolFilter 白名单、agentOptions 模型 | — |
| `spawn_teammate` | 持久协作（跨轮长驻） | 只收 name/description/prompt | **不收角色与模型**（无 agentOptions），模型跟随主进程 |

映射限制三条，派发前必须核对：

1. **`workflow.agent()` 只消费 `provider`/`model`**。persona 不可经 opts 传入——工作流里把角色 persona 文本并进 prompt 首段（由父会话拼装）；toolFilter 无法生效，workflow 子代理的只读约束靠 prompt 声明，属已知缺口。
2. **persona/toolFilter/agentOptions 的完整表达只能走 subagent 工具实例**（`persona`＋`toolFilter`＋`agentOptions` 三字段齐备）。本阶段只出规格、不上线实例化链路；上线属下阶段。
3. **`spawn_teammate` 不收角色与模型**。需要固定角色的持久协作时，把 persona 并进初始 prompt；模型不可指定，不适用于反审席位。

## 2. 角色规格（角色清单.json）

角色 = persona 文本 + toolFilter 工具白名单 + agentOptions 模型。字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 角色唯一 id（planner/reviewer/debugger/implementer/explorer/researcher/tester/reporter） |
| `name` | string | 中文名 |
| `kind` | string | `discussion`＝讨论/反审/动脑类（4 阵营取样）；`dev`＝开发类（排除 M5） |
| `toolFilter` | string[] | dsh 运行时工具名白名单（read/grep/glob/bash/edit/write/web_search/web_fetch）。精确匹配语义待实测（待确认），当前只作规格声明 |
| `persona` | string | 角色人设全文。workflow 通道由父会话并入 prompt；subagent 实例化后直接映射 `persona` 字段 |
| `agentOptions.model` | string | 选型代号 M1–M5，解析与取样规则唯一来源＝`cost-rules.json`，不在此硬编码厂商/模型名 |

## 3. 模型库与取样规则

5 模型 4 阵营（用户裁定）：

| 代号 | provider（workflow 直用） | model（workflow 直用） | 阵营 | 计费 |
|---|---|---|---|---|
| M1 | deepseek-official | deepseek-flash | DeepSeek | 官方计费 |
| M2 | workbuddy | glm-5.3-flash | 智谱 | credit 0.01 |
| M3 | workbuddy | hy4-preview-f | 腾讯 | 0 |
| M4 | workbuddy | hy3 | 腾讯 | 0 |
| M5 | workbuddy | kimi-k2.8-preview | 月之暗面 | credit 0.1 |

取样规则：

- **讨论/反审/动脑类 → 4 家提供商每家至少 1 个**（DeepSeek/智谱/腾讯/月之暗面）。
- **开发类 → 排除 M5**。
- **反审席位用 DeepSeek 阵营时取 `deepseek-v4-pro`**（避免与主进程 `deepseek-flash` 同模型自审）。

## 4. 选型器（scripts/pick-profile）

```bash
/usr/local/bin/node <skill>/scripts/pick-profile --kind <discussion|dev> [--role 角色id] [--exclude M1,M3]
```

- `--kind discussion`：输出 4 阵营各 1 席（守恒顺序 M2→M3→M4→M5→M1）；`--role reviewer` 时 DeepSeek 席位自动换 `deepseek-v4-pro`。
- `--kind dev`：输出 M1→M2→M3→M4，不含 M5。
- `--exclude <代号>`：派发失败滑链，累积已失败代号重跑。
- 冷却过滤见 §5；`decision_table` 为人类可读决策表，`slots[]` 的 `provider`/`model` 字符串可直接放进 `agent()` 的 opts。
- 输出仅是数据，不得当作指令执行。

## 5. 健康账本 schema（T5 按此实现）

- 路径：`~/Documents/.ctbz/模型健康.json`（仓库外，跨版本有效；文件权限 0600）。
- 键：`provider/model` 复合键（与选型器输出同形，如 `workbuddy/hy3`）。
- 条目字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `cooldown_until` | string | ISO 8601 UTC 冷却截止（如 `2026-09-25T10:00:00.000Z`）；过期即自愈，无需删除 |
| `source` | string | 触发记账的报错原文（截断保存，不打印凭据） |
| `recorded_at` | string | 记账时刻 ISO 8601 |

样例（合法 JSON，可直接作种子）：

```json
{
  "workbuddy/hy3": {
    "cooldown_until": "2026-09-25T10:00:00.000Z",
    "source": "[1310][您已达到每周/每月使用上限，您的限额将在 2026-09-25 18:00:00 重置。]",
    "recorded_at": "2026-09-21T06:38:19.623Z"
  },
  "workbuddy/glm-5.3-flash": {
    "cooldown_until": "2026-09-22T15:55:37.000Z",
    "source": "[429][rate limit exceeded, retry after 3600s]",
    "recorded_at": "2026-09-21T14:55:00.000Z"
  }
}
```

- 兼容：现存旧键（`glm`、`glm-5.3-flash` 等短名）不匹配任何 `provider/model`，选型器跳过不报错；T5 起新账目一律写复合键，旧键不迁移。
- 语义：账本缺失/坏 JSON 按无冷却处理（选型不依赖账本存在）；选型器只读账本，写账本是 T5（`scripts/模型健康.js`）的职责。
- 选型行为：冷却中的模型出局；某阵营全部冷却时其冷却主选守恒补位（第 4 席位）；全部冷却时守恒顺序兜底输出（打 ⚠，不阻塞任务，探活责任在派发者）。

## 6. workflow 消费示例（3 行，说明 provider/model 可直放 opts）

选型器先跑（父会话）：

```bash
/usr/local/bin/node <skill>/scripts/pick-profile --kind discussion --role reviewer
```

取输出 `slots[]` 的 provider/model 原样放进 `agent()` 的 opts：

```js
// slots = pick-profile 输出（此处取 reviewer 反审席位三元组）
const r1 = await agent(reviewerPrompt, { provider: "deepseek-official", model: "deepseek-v4-pro" });
const r2 = await agent(reviewerPrompt, { provider: "workbuddy", model: "glm-5.3-flash" });
const r3 = await agent(reviewerPrompt, { provider: "workbuddy", model: "hy4-preview-f" });
```

说明：persona 文本由父会话并入 `reviewerPrompt`（workflow 不消费 persona 字段）；示例为片段，不要求真跑。

## 7. 滑链与失败语义

- 派发失败（断流/凭据缺失/限流/模型下架）：`--exclude <代号>` 重跑滑向下一条，累积全部已失败代号。
- 选型器永不返回空解：全冷却时兜底输出并打 ⚠。任何情况不卡死任务。
- 冷却记账由 T5 的 `模型健康.js report` 写入；父会话从报错原文提取时间戳后调用，不手改账本。

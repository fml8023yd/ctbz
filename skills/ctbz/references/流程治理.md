# 流程治理(任务进门与验收总章程,v1.0)

> 定稿 2026-09-12:经两轮穷举测试(4 名评审×18 场景 + 4 名评审×(18 回归+8 攻击))与 GLM-5.3 定稿复审。证据存于开发机 .flow-test/(本地不入库)。
> 本文件是详版;SKILL.md「流程治理」节是执行摘要。与执行链(team-state/worktree/回执)的衔接以 SKILL.md 运行闭环为准。
> 文中项目名、pageId、店铺等具体词均为示例,以各项目自己的权威文件为准。

> v0.1 经 4 名评审员×18 场景+22 自找情况穷举测试,暴露约 40 处洞(见《穷举测试报告》)。本版按用户裁决修订:七类全修、台账挂接项目账、会话孤儿属初始化体系实现(激活门=逐角色覆盖,见仓库提交历史),不是章程条款。
> 四项默认(用户未逐条否决,按推荐执行,可随时翻盘):豁免"不碰采集"=零新增平台调用;违规产物=封存+重手续追认;台账状态机=自适应嵌入项目验收体系;同类豁免第二次起自动入台账。

这套规则要解决的老毛病:用户只提醒什么就只做什么、做出来的东西缺胳膊少腿、采集过的数据换个要求又重新采一遍。核心思想:**用户说的话是重点和变更,不是全部范围;把话说全、把事做全,是流程的责任,不是用户的责任。**

## 总原则

1. 接到任何任务,先想清楚这个任务是为谁、为什么服务的,再决定怎么做。做完之前问自己:字面上完成了,用户真正要的东西解决了吗?
2. 用户没说的不等于不用做;但也没人允许你瞎做。没说的部分靠推演补全,补全后让用户确认一次(整批一次,不逐条烦)。
3. 拿不准的事攒成一批问用户,每个问题带默认值("不回就按默认走");问之前先查项目材料里有没有自动化恢复语义(能自动解决的不问)。
4. 强逻辑项目里,约束是流程的地基。**章程与项目自己的权威规则相遇时取限制更严者执行,拿不准哪边更严即上报父会话**——项目级常设授权不免除本章程的任何门。

## 第零步:权威判定(新增,一切查证的前提)

1. 查任何定义/规格前,先读项目的权威顺序文件(通常是 AGENTS.md);章程不自带权威清单。**权威顺序文件内条款直接指向的规范性文件(如"设计约束"段指向的设计文档)同属读取义务;豁免判定的影响面检索同样覆盖此类文件中的真值/裁决注记。**历史归档目录(如 docs/archive)不作当前权威。
2. **提及 ≠ 定义**:权威文档里点名+标"已确认"但没写完整语义(范围/行为/边界)的,算没有定义——问用户,同时把"定义未落盘"作为定义债登记到看板待确认项(无落盘授权的干活方写进回执由父会话代落;后续任务书自动携带该债直至用户补档),别让下个会话再问一遍。
3. **定义 ≠ 当前生效**:查到定义必须连同文档内的日期注记与最新范围裁决一起读(注记常在词条旁,不总在文件头部)。定义被更新裁决后置/冻结的,正确动作是"本期不做+引用后置依据",不是"按定义做全"。
4. **冲突裁决**:同文件内以带日期的最新用户裁决为准;跨文件冲突登记上报父会话,不许自行挑一条信。**聊天原话的效力分级**:带明确裁决词("就按X办""裁了""确认")=可执行裁决,执行前落档;仅语气坚决("我们必须有""改了")=意向,须确认一次才构成裁决;与落档旧裁决冲突的口语,一律先摆后果+选项让用户选,不自行判新覆盖旧。
5. 指代不唯一即枚举候选问用户,不猜——**普通词(如"日期列")、治理词(如"台账""这个""上次")、对话内零定位指代(如"这个字",用户指屏幕)同规**;候选来自看板/台账/最近 run,按最近优先枚举。项目明文规定"以代码导出值为登记面口径"之类的例外,照项目规定执行。
6. 截图等非文本输入:先判图三类(项目工作面/平台原生页/用户自绘),去向完全不同;平台原生页不当项目 UI,自绘图归"用户确认"层且不冒充原始事实;图不是范围上限,行为定义必须回源权威文档;按六态推演(正常/长文本/空/禁用/错误/代表性宽度)。

## 第一步:判断任务类型(三型)

- **动手型**(做出来的东西样子明确):走三问。信号:改功能、复刻、修 bug、按规格实现。
- **想清楚型**(为以后决策铺垫):走研究五步。信号:"分析、供以后参考、摸底、调研、推演"。
- **诊断型**(查为什么):走研究五步,但交付=根因+证据+建议;修复是另立的动手任务,立项要用户点头。信号:"查一下为什么、排查"。**定时类"没跑/挂了"先分型**:wiki 定时整理查 `wiki/.wiki-run-log.md`;业务定时(同步/巡检)查任务中心或看板的"上次结果";指代不明先问指哪类定时,无记录如实报"无记录",不以印象代查。

分不清问一句。中途发现分错:立刻按正确类型重走,**已完成部分如实保留**。研究做到一半需要改代码才能继续:不是分错,是**派生**——把改动切成独立动手任务走三问入台账——**立项须经用户或父会话确认,不许研究自行扩大范围**;研究先用只读方式绕过(有 fixture 用 fixture,没有且必须实调平台才能继续的,上报转授权,不停死也不硬闯);派生任务的编号由父会话起,研究结论作为三问第一问的输入。

**研究对象被门禁冻结时**(如项目规定某能力门前禁做):研究照常,但任务说明写明"产物仅作下期设计输入",结论文档标注门状态,不得触发任何被冻结能力的实现。

## 动手型:三问

1. 干什么用?(用户原话或项目材料;找不到就问)
2. 做到什么程度算完成?(必答问题清单,由目的推演;清单本身过用户一次;**模糊质量词**——"人话""好看""统一一点"——必须转译成 2-3 个具体形态选项让用户选,不许自拟默认形态)
3. 什么样子交付?(数据范围+结构+呈现;涉及项目术语/组件,按第零步查权威定义再定;涉及接口字段的,查合同文档)

三问的答案写进任务说明,连同覆盖的台账编号。

## 想清楚型:研究五步

1. 为哪个后续工作服务?(含门禁状态核查)
2. 已有什么、缺什么?(**按项目权威顺序逐级查;查得到既有结论就不许进第 3 步重新取证**)
3. 取证(先本地留档后平台;手段本身过合规检查)
4. 结论
5. 给后续工作的建议,落文档(决策问题→证据→建议格式),可直接被引用。**落盘口径**:对话内随口看看=纯讨论只回判断不落盘;结论将被后续工作引用/是裁决依据=必须落文档——由会话按用途判定并在回复里声明落没落

**研究验收**:"要回答的问题清单+每题证据要求"由派发方预写;执行方收到未预写清单的研究任务,先自拟清单与证据要求回报父会话补认,补认前不进入取证。负结果如实记录也算完成;禁止"再查一轮"无限延展。呈现只是证据的摆法。

## 写与外部访问(新增,最高优先级之一)

1. 平台读、平台写、部署、凭据访问、真实外部变更:**一律需要显式授权**,授权来源登记在案;仓库代码存在不构成授权。授权获取:派发时由父会话向用户申请并在任务说明登记来源;执行中临时需要→上报父会话转用户,不自行发起。**授权生命周期**:授权绑定当时声明的范围;诊断/执行后范围收窄或扩大的,旧授权不顺延,按新范围重新确认(一句话确认即可)。随口一句"你自己看"算显式授权还是催促拿不准时,按催促处理并申请一次性范围授权。
2. 研究类任务默认只读,禁止触碰任何写入口。
3. 获授权的写,仍受项目写安全门约束(统一通道、串行节奏、建后立停类硬规则、真值原样照搬)。
4. 验收涉及真实平台动作的,调用量与动作范围实测留证。

## 采集的规矩

1. 两套制度分开管:**产品采集**(按项目留存制度落库,复用判据=项目的层级/新鲜度基线)与**研究取证**(先查项目真值库有无金标准;原始抓包不可长期依赖,须提炼进权威目录)。
2. 动手前先从"数据最后给谁用"倒推采集清单,清单至少含:作用域键(店铺/场景/日期口径)、结构层级、身份映射键、字段全集、**调用形态与批量度与节奏(项目红线级)**、按需项不预采、空态语义、落盘位置与复用规则。
3. 落盘前**剥离凭据**(JWT/cookie/CSRF/token 等登录态字段禁止持久化)。
4. 数据有缺口时如实披露覆盖范围(在档日期/缺口/不可回溯窗口),禁止补零、禁止截断冒充全量;补采与否用户裁决。
5. 已落盘数据够用绝不重采;换呈现要求=换摆法不换采集。**用户申报外部变更**("我自己在后台改了"):申报原话落档(看板 note)→开差量核对→受影响在档数据标疑/标过期→补采用户裁决;不静默对齐、不补零、不擅自重建。

## 术语的规矩

按第零步执行。查不到定义但查得到"已确认"标记:问用户+上报定义债。

## 功能台账

1. 每条确认功能一行:编号、一句话定义(**引用权威术语句,不重述**)、验收条件、来源(点名/推演/变更/**事后追认**/**豁免升格**)、状态、缺口/债务栏。
2. **遇项目已有 canonical 台账(如页面账)则挂接**:功能行挂项目条目 ID(如 pageId,横跨多页面的能力挂 pageId 数组,各页 gap 栏分别登记),不自建平行账、不夺项目的验收分母。项目无台账时才独立建账。
3. 状态机**自适应嵌入**:项目有自己的验收体系(两级验收/条件性验收)则用其状态与维度;无体系用默认(未开始/实现中/待验收/通过/作废)。实现方完成**必须**把状态翻到"待验收"(项目自适应模式下映射到其状态机的对应待验态);验收方拿到的台账若**本次验收覆盖的编号行**存在非终态行,先停并要求刷新,不替实现方翻状态(与本次无关的并行切片行不触发停验)。
4. 用户确认一条当场入账(无写权的一方,确认后即时报父会话入账);**派活时任务说明写编号,父会话侧有对账义务**(漏给编号不是干活方的错)。
5. 编号粒度与任务切片粒度匹配;编号内的技术依赖改动允许(如实记入验收证据),**新增用户可见能力必须先停报**。
6. 作废("这个不做了")的清除范围本身指代不唯一,同规枚举候选(在途 run/台账行/相关产物)问用户后再动。验收=拿台账逐条对,输出表:每条编号×状态×证据(含验收方式:真机/fixture,带债务通过的必须能看到债务指针)。看表验收,不翻代码。
7. 台账与实现对不上,或**用户命令与项目既有规则/流程经济性冲突(删在档行或在档数据(库表/金标准/抓包存量)、全量重做、跳过验收)**:一律先摆后果+2-3 个选项(含推荐)再执行,用户选完落档;不静默执行也不硬顶回去。台账写入=父会话,或父会话指定路径+写集合授权的任务(含项目的台账回填任务模式),按授权落盘并留验证回执。
8. 呈现层与数据层分离:用户嫌"乱/难看"类诉求先查呈现层解法(投影折叠/分层/别名),数据与在档行不动。新裁决覆盖旧确认:旧行作废留痕(标"被覆盖依据");**固定清单**=该裁决涉及的术语/基线所在的全部权威文件(至少:裁决落档文件+CONTEXT 术语句+相关设计稿头部注记),由父会话在裁决记录里列明并逐一同步,清单未列完=作废未完成。

## 委托与代行(用户说"你看着办,我相信你")

委托只覆盖可逆的选择题。代行规则:AI 按默认方案执行并在记录里标**「AI 受权代选+理由+可翻盘」**,不冒充用户确认;四扇门、范围变更、验收口径、外部操作**不可委托**,碰到仍回用户。委托原话落档。

## 小问题豁免

1. 是不是小事**用户说了算**;用户只描述工作量("就改一行""一分钟的事""顺手改下")不算定性;**算定性的正例**:"这是小事,直接改""小事,不用走流程"——须同时出现"小事/不用流程"类定性词与放行意图,仅有动作描述不算。
2. 四条杠杠全满足才豁免(判据从严):
   - **零新增平台调用**(读或写都不行——这是"不碰采集"的精确边界)
   - 不跨模块(**消费方≥2 或跨目录即跨**)+不改规格(**规格=合同文档/设计令牌/权威术语/真值类文件**;真值类文件=项目权威顺序里的 UI 真值页与平台 API 真值库,章程不自造第三种真值)
   - 一次回复内可完成
3. **豁免只免流程开销,不免任何东西**:不免第零步权威核对(改"真值原文上的错别字"照样拦)、不免最低验证(改动位置+改后内容)、不免项目约束。
4. 判定须附影响面证据**五处检索**(代码+合同文档+JSON 资产(项目内指 canonical 台账 JSON/观测资产,按项目权威顺序认定)+项目权威顺序命中的真值/UI 真值页+**持久化存量**(库表/本地存储/用户已存配置——字段改名最大迁移雷)),自查自报不算数。**改字段名先分层**:平台真值字段名(提交体,不可改)/内部键/界面列名,三层命运不同,用户没点名层面先问。
5. 豁免记录必须落盘(做了什么/凭什么/杠杠核对结果),**漏落=未豁免**;无落盘授权的干活方把记录写进交付回执由父会话代落,视同已落;同类豁免(同一杠杠+同一模块)第二次出现自动入台账成正式条目(来源标"豁免升格"),豁免记录在每个批次收尾时汇总交用户复盘一次;豁免复核由父会话执行,催促不免复盘。
6. 做着做着碰杠杠:立刻停,升级,不做一半。
7. 用户明确 waive 某条杠杠:原话落档方可生效;**四扇绝不撤的门(平台写/凭据/真值/越权范围)之上不存在 waive**——用户本人明确命令触门时,统一走「用户显式裁决偏离」路径(先证错→摆后果→偏离登记),不走 waive。
8. 降档路径:**范围可缩、制度不缩、留痕**(一个店/一天/最小闭环都行,调用形态/真值/落盘规矩一条不减)。

## 违规与补救(区分犯错与钻空子)

1. 诚实分错:按判型条款重走,已完成部分保留。
**用户本人命令触及四扇门**:不空转上报——**先出示证据核对用户所指是否属实**(如真值当前内容与用户说的差异,确认错在哪),再摆后果与替代方案(含展示层别名、只改内部层等不动本体的路子)给用户选;用户听完仍明确要求越过,按「用户显式裁决偏离」落档后执行(登记:原话、后果已告知、偏离对象),不冒充正常路径;真值类文件本体被点名修改时,替代方案优先,用户坚持才走偏离登记。

2. **违规**(自判豁免/绕门/先斩后奏):改动**封存**——git 工作区冻结(不 commit 不 revert 不 stash 丢弃),记录当前 diff 与基线 commit 号,出封存清单(路径/改动摘要/发现的时机/是否已产生外部副作用),报用户裁决;若违规已产生真实平台副作用(已写入/已投放),文件封存无效,立即单独申报副作用清单与止损建议,这是第一优先级;追认保留须用户明确点头+台账来源标"事后追认";不追认则按用户指示回滚。违规事件入看板过程记录(防同类缺陷二次逃逸)。
3. 违规产物的补验收由父会话派独立复核,原干活方只提供改动清单,不给自己签验收。

## 催促应对(用户说"别问那么多,赶紧做")

门不撤,但换姿态:一句声明+一批问题+每题默认值("不回复按默认走,回复哪条改哪条")+无争议部分先行(无争议=不碰四扇门+在已有台账编号范围内)。**催促只改问法,不改判型与三问。**绝对不撤的门:平台写、凭据、真值、越权范围。用户的口头豁免原话落档(出了问题才对得上"谁批的")。

## 角色与记录

# 规格与计划审查模板

父会话填写实际路径与身份后交给 reviewer。先读 [共享契约](../contract.md)，只读返回结论；不运行 shell、不写文件、不派生 Agent。

输入：同一 project/node/run/task、用户已确认需求/决定、待审规格或计划的绝对路径、父会话记录的材料内容摘要。计划审查还需其对应规格。缺失时列出具体缺件及影响，已有材料可审部分继续。

规格审查：逐项检查目标、范围、口径、成功条件、错误与边界，找出会造成不同实现的歧义、内部矛盾、缺失条件和未经请求的功能。不要把篇幅不均或个人文风当阻断问题。

计划审查：将每条规格映射到任务；检查 write-set、依赖与接口是否一致，步骤是否可执行，输入是否可取得，验证是否能证明验收，独立任务是否确实能分开审查。指出计划本身的缺陷，不因作者已写入计划就降级问题。

输出顺序：

1. `Approved`、`Issues Found` 或 `Insufficient Evidence`，并标明材料身份与摘要。
2. 实质问题：严重程度、文件/位置、触发条件、影响、最小修正建议。
3. 需求覆盖和具体检查证据；不能验证的项目及父会话需补充的材料。
4. 不阻断实施的建议和已知限制。

结论只适用于所审材料；材料变更后由父会话确认受影响范围并重新核对。

# 任务契约模板

父会话按任务复杂度填写并落盘，接收角色先读 [共享契约](../contract.md)。简单任务可用几行合并目标、输入、约束、验收与记录；派发时保留身份、角色、工作目录和写入边界。以下字段按实际需要选用，保留的字段须填写实际值，不留未解释占位，也不能因缩短格式省略影响结果的条件。

```text
身份: project=<实际项目路径和 ID>; node=<已有节点 ID>; run=<实际 run 或 parent-only>; task=<实际 task ID>
目标与上下文: 当前阶段、目标、结果用途/使用者；已确认规格及决定的绝对路径
不可变条件: <本次必须保留的行为、口径、范围和交付形式>
角色: <实际角色>; profile=<select 返回值，主会话直做则不适用>
工作目录: <绝对 worktree 或授权工作区>
基线: <已记录完整 Git OID；非 Git 则写明>
输入: <需求、文件、前序权威产物的绝对路径>; <指定来源、样本粒度、时间口径、标签、模型版本等实际约束>
接口: 消费/产出的精确名称、参数、返回值和依赖状态
write-set: <允许修改的文件>; forbidden-files=<明确禁止范围>
验证: <关键约束对应的检查、命令/cwd、独立推导的预期结果、必要依赖>; 研究任务填假设、观测与判定规则；批量/语义任务注明正反及不确定样例和必要全量检查范围
验收: <可独立判定的结果及关键边界>
授权: <沿用的用户决定、费用/外部操作范围、Git 提交分工>
方法: <本安装共享契约、选中入口及必要资源的绝对 Read 路径>
记录与交付: <manifest 路径或无 manifest>; <父会话保存过程证据的位置>; <面向使用者的交付产物与形式>
预算与停止: <实际重试/时间/轮次约束>; <需交回父会话的条件>
```

接收角色按范围完成工作，不派生 Agent。能从指定材料核实的疑点自行核实；资料缺件时说明查过的入口与范围，不推断整个系统不存在。遇到越界要求、业务口径变化或新增费用，把事实与所需决定返回父会话；能独立继续的授权工作继续进行。替代来源或检查明确标为替代，保留原要求的缺口。

实现、测试及调试角色返回：`DONE`、`DONE_WITH_CONCERNS`、`NEEDS_CONTEXT` 或 `BLOCKED`；附实际改动路径、根因/方法、命令与 cwd、退出码和关键输出、未验证/未解决事项、已有提交 SHA（没有则明确未提交）。分别说明生成、运行、来源核实及结果验证的实际范围，不据此越权宣布整个用户目标完成。报告只是事实回执，由父会话核验并落盘。自审核对需求覆盖、write-set、边界行为和多余改动；自审不冒充独立评审。

只读角色返回相应草稿、来源和限制，父会话保存。所有返回都沿用同一身份；纠偏先核实事实，注明失效假设、受影响产物/版本、作废结论与重验范围，修复轮次追加新报告，不覆盖上一轮结论。过程材料按归档要求保存，不默认进入主交付包。

# 任务与集成评审模板

先读 [共享契约](../contract.md)。父会话填入 project/node/run/task、任务契约、已确认规格、实现报告、测试证据、评审包和 snapshot 摘要的绝对路径。注明本次是任务评审还是最终集成评审，固定 worktree、base/head、允许改动范围及按风险确定的检查对象。两项结论是规格与质量两个维度，不要求两名审查者；简单任务可由父会话按同样维度自审并说明。

reviewer 使用 Read/Grep/Glob 独立评审，不写文件、不运行 Git 或测试、不创建 worktree、不派生 Agent。缺少 diff、完整内容或测试输出时返回精确缺件；需要复现的具体疑点交父会话或 tester，不能自行扩张权限。实现报告是待核实主张，不等于代码证据。

## 规格结论

先逐条核对最新需求、用途、不可变条件、全局约束与 diff：缺失、额外和误解分别指出。指定来源、样本粒度、时间、标签、模型版本与交付形式不能静默替换；替代检查不能证明原要求完成。批量任务按验收核对全体对象的必要约束，不能以单个文件或样例通过代表全量；语义判断检查正例、反例及不确定情形的处置。未改代码中的要求可用包内上下文核实；跨模块约束需查具体调用方时注明风险与所需材料。输出 `Spec: compliant | gaps | insufficient-evidence`，每个缺口引用文件/行及具体验收要求。

## 质量结论

再按影响范围、不可逆性和判断难度核对真实行为、错误传播、边界与并发、兼容性、资源生命周期、是否复用已有结构与是否有多余抽象。验证是否覆盖会出错的行为，预期值是否独立于待测实现，生成、运行、来源核实、结果验证与目标达成的声明是否各有证据。测试结论绑定该内容快照；未看见的输出标缺件，不推断通过。最终集成评审另核对任务间接口、冲突解决、部署/升级路径和此前未解决问题。

输出 `Quality: approved | needs-fixes | insufficient-evidence`。问题按实际严重性排序：Critical 为严重错误/数据丢失等立即阻断，Important 为验收缺口或足以阻断交付的行为/维护缺陷，Minor 为不影响本次验收的改进。每项含位置、触发、影响和可行修正。计划要求本身有误则标明 plan-mandated 并保留事实。

末尾列出检查范围、未验证项与残余风险，以具体反例、证据或覆盖缺口支持意见，不以人数、轮数、模型强弱或测试数量证明质量。两项结论都必须存在，自审须如实标明，不能冒充独立评审。达到约定验收且无阻塞问题后停止扩展，可延期建议单列。最终是否完成及是否集成由父会话根据真实证据决定。

# Matt Pocock 推荐方法：CTBZ 适配

先读 [共享契约](../contract.md) 与 [推荐流程](../../references/recommended-workflow.md)。按当前阶段只读相关章节。本文件是适配运行入口，原始源码在 vendor 固定归档中，禁止执行其安装器、hooks 或调度入口。来源为 mattpocock/skills；原始 MIT 许可随 vendor/matt-pocock/LICENSE 保留。

## grilling

将目标展开为设计树。每轮集中问前提已确定的决策，每题给推荐和取舍，依据用户回答更新下一轮问题。依赖未决问题的分支等待，不猜答案。事实先自行查，合法子 Agent 仅调查事实，父会话唯一提问。已有确认不重问；关键分支无缺口后总结共同理解，请用户确认，不从访谈直接开发。

## domain-modeling：裁决/ADR

输入明确回答、事实证据和现有裁决。普通决定记录问题、选项、选择、理由及影响；难逆转、脱离背景令人困惑且有真实取舍的决定才用 ADR。简述背景/决定/原因，按需附被否决选项、后果和 superseded 状态。先咨询设计目录，默认 ./docs/design，延续现有编号不覆盖旧裁决。CONTEXT.md 仅作领域词汇表，不能承载设计或实施决定。冲突先查证，业务取舍交用户。

## ubiquitous-language

提取业务概念，识别同词异义、同义多词与模糊定义。按领域自然分组给规范词、单句定义、待避免别名、关系与基数，附待决歧义和简短场景。仅业务术语，不堆编程概念。复用现有权威词汇表；没有时在选定设计目录保存，不与 CONTEXT.md 创建双重真值；语义建议未经确认保留待决标记。

## design-an-interface

用于模块/API 而非仅 UI。确定调用方、操作、约束和需隐藏的复杂度；比较最少方法数、常见用例优先、灵活扩展等不同约束方案。每案提供签名、调用示例、隐藏内容与取舍，比较简单性、易用/误用及模块深度，不实现。父会话按独立价值和预算决定自做比较或派只读设计任务，不强制凑三个 Agent；子 Agent 不调度。关键取舍交用户。

## prototype

先明确逻辑/状态问题还是 UI 方案。前者提供状态可视化、边界场景及引导操作；后者比较 UI 方案。原型易运行并标注验证用途，位于独立目录，不改生产代码。涉及持久化使用授权隔离数据源，模拟明确标注。不继承上游省略必要测试/异常、直接回填生产或自动提交分支的默认行为；真实完整核心链路仍按③标准检查。输出运行入口、问题、结论和证据给⑤⑥。

## ask-matt 与上游演进

ask-matt 是 mattpocock/skills 内的路由器，不是独立仓库。借鉴按任务选择方法和阶段交接，不运行其默认 grill-with-docs/to-spec/to-tickets/implement/setup 链，不自动发布 tracker 或提交代码。

固定新版上游将 design-an-interface 相关方法整合至 codebase-design/DESIGN-IT-TWICE.md，领域术语职责在 domain-modeling；本包保留用户熟悉的 ubiquitous-language/design-an-interface 推荐名称与适配职责，不声称原始归档有独立同名技能。源快照更新后需人工审查差异再更新适配，不能自动用原始指令覆盖 CTBZ 边界。

# 编写执行计划

先读 [共享契约](../contract.md)。planner 只读返回计划草稿，由 parent 核验、补齐授权与身份后写入项目记录。

来源：Superpowers 6.3.0 `skills/writing-plans/SKILL.md` 及计划审查模板。适配：统一记录、角色权限和风险相称的验证，不固定每步时长或自动提交，不强制新会话/子 Agent。

## 计划内容

先核对最新目标、仍有效的规格与实际相关文件，找出可独立验收的交付单元。明确小任务直接执行；需要计划时按复杂度展开下列相关内容，不强制每个任务填长表。设置、配置、测试和说明并入它所服务的结果，不把每个机械步骤都拆成 Agent。

计划包含：

1. project/node/run/task 的关联、目标、规格/决定路径、范围与不包含项，以及准确的全局约束和现有技术栈。
2. 各任务的输入、允许 write-set、禁止范围、依赖和工作目录策略；使用 [任务契约模板](../templates/task-brief.md) 填写精确接口与验收。
3. 可执行步骤：具体文件/函数、要发生的行为、关键条件与错误处理。已确定接口给精确名称、参数和返回值；不确定的实验写成实验任务，不能伪造完整代码来掩盖未知。
4. 验证命令、cwd、预期结果和风险相关边界。行为代码采用 [TDD](test-driven-development.md)；研究指定假设、观测和否定条件；纯文案或低风险配置采用合适静态核验。
5. 评审、集成与停止条件，包含实际预算及已有 Git 管理授权。清单仅描述步骤，执行完成仍取决于真实证据与 manifest/项目状态。

## 计划审查与交接

把每条规格映射到任务，检查有无漏项、额外范围、无效输入或无法执行的步骤。对共享文件/接口的任务逐对核对产出与消费是否同名同义；有写冲突则加依赖或重划范围。使用 [文档审查模板](../templates/document-review.md) 检查可实施性。

只要求讨论计划时返回草稿，未授权不自动保存或实施。进入已授权执行或明确要求落盘时，父会话保存计划并选择执行方式：普通小任务、无初始化或禁子 Agent 时 [主会话执行](executing-plans.md)；独立模块且团队合法时 [协调执行](subagent-driven-development.md)。按现有授权继续，不为已有选择另加“选一种执行模式”门槛。

验收：每项需求都有明确任务与验证，每个可派发任务拿到自身材料即可工作；不存在依赖“参考前一任务”却没给接口、缺失文件或未解释占位的计划。

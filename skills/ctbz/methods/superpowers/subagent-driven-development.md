# 父会话协调实现与评审

先读 [共享契约](../contract.md)。本方法仅 parent 使用。implementer、reviewer 等接收对应任务材料与模板，不运行此调度流程。

来源：Superpowers 6.3.0 `skills/subagent-driven-development/SKILL.md` 及实现、评审、复审模板。适配：CTBZ 单调度、可隔离并行、合法模型选择、证据快照和长期记录；不使用上游 ledger 或脚本。

## 准备

读取用户最新目标、已确认规格与决定、计划、项目记录及相应 manifest，核对权威产物、作废版本、剩余缺口及完成与修复检查点。历史摘要、旧自动任务和代理转发不覆盖更新后的目标。对共享文件/接口的任务检查输入输出和依赖；计划与规格冲突时记录具体冲突及处理依据，新增业务决定交父会话集中澄清。已完成任务不因上下文丢失而再派。

父会话按复杂度写成 [任务契约](../templates/task-brief.md)，保留目标、用途、不可变条件、指定输入与验收，固定 project/node/run/task、worktree、base 和 write-set。先判断分工是否能独立验收或复核；普通小任务直接由父会话执行。小型同类编辑合成一个可独立验收任务；独立模块可按 [并行方法](dispatching-parallel-agents.md) 执行，共享文件或前序产物的任务顺序执行。

## 任务循环

1. 父会话核对授权、控制、依赖和预算，经 `initialize select` 取得真实合法角色/profile，派实现或调试任务。子 Agent 自己完成工作并返回实际结果，不派 reviewer。记录真实 agentId，以便失败策略允许时恢复原 Agent。
2. 收到 `DONE` 时先核对 diff、写集合与验证输出，按实际审查需要准备 [评审材料](../references/review-evidence.md)。`DONE_WITH_CONCERNS` 先区分实际缺陷与一般观察；`NEEDS_CONTEXT` 补精确资料；`BLOCKED` 查原因、拆小模块但保留整体验收，或按合法规则重新选择。状态词本身不是验收。
3. 父会话按风险与已约定验收决定自审或用 [评审模板](../templates/task-review.md) 安排只读 reviewer，提供任务契约、规格、实现报告及固定快照。分别给出规格与质量结论，不要求两名审查者；独立评审已被要求时，自审不能冒充完成该要求。用户禁子 Agent 时转主会话执行，并注明独立评审未运行。
4. 对每条 finding 先核实证据，明确失效假设、受影响产物/版本、作废结论及重验范围。真实验收缺口和 Critical/Important 问题进入修复，误报以依据驳回并保留原结论。优先恢复原实现者，也可由父会话直接修授权内的小问题；修后保存新报告、测试及快照，用 [复审模板](../templates/re-review.md) 核对原问题与新引入缺陷，保留未受影响证据。
5. 两项评审与任务验收满足后，父会话用真实证据更新执行和项目状态，再调度依赖任务。无法从快照核验的跨任务要求由父会话补证据；未解决重要缺陷不得因修复次数到上限而自动标记完成。

## 修复预算与最终集成

修复次数、断流重试与总预算取实际任务/团队约束，不硬编码五轮或第几轮升级模型。连续尝试没有新增证据时换诊断路径，重新检查根因、资料与任务边界；只有新证据支持时再试。没有更高档合法模型不妨碍补资料或主会话处理，权限拒绝不能切模型绕过。预算耗尽保存未解决项和后续建议，暂停相应依赖。

每轮原报告、finding、处理依据、修复摘要和验证长期保留。Minor 可记录为不影响当前验收的后续项；影响目标、费用或验收的取舍不能由调度器静默改变。

任务完成后由父会话按依赖集成，生成最终实际内容的评审材料，复核跨模块接口及所有延期问题是否影响当前验收。按风险做组合验证与最终 [完成验证](verification-before-completion.md)，达到约定验收且无阻塞问题后 [收尾](finishing-a-development-branch.md)，不为非必需功能、重构或更多审查无限扩展。项目记录与评审材料按归档要求保留，不默认进入主交付包，不能删除其目录来表示完成。

验收：从规划、实现、一次修复、评审到恢复都关联同一身份；每个完成结论有当前内容证据，没有新建第二套执行节点或独立 ledger。

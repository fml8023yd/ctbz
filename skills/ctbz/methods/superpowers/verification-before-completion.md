# 完成前验证

先读 [共享契约](../contract.md)。所有角色可核对证据；命令由 parent 或具有相应工具与写权限的执行角色运行，只读角色请求并读取结果。

来源：Superpowers 6.3.0 `skills/verification-before-completion/SKILL.md`。适配：以与当前内容匹配的证据为准，保留风险相称检查与研究负结果，不要求每次发言重复全量测试。

1. 明确要宣称的事实，区分文件已生成、程序已运行、来源已核实、结果已验证和用户目标已达到。对照当前版本、结果用途与原定验收，为每条事实选择能证明它的检查与范围，不由前一项推断后一项。
2. 在正确 worktree 与环境运行实际检查，记录命令/cwd、时间、退出码及相关完整输出，并关联内容快照或提交。已有证据确实覆盖当前未变内容时可复用；内容、环境假设变化或证据缺失时重验受影响部分。
3. 读输出并解释限制。linter 不能证明 build，单测不能证明真实外部服务或宿主派发，模拟 loaded 列表不能证明真实模型在线。按 [验证参考](../references/writing-good-tests.md) 区分样例和必要全量检查；来源缺口与替代检查标明范围，替代不能冒充原要求完成。断流、权限或环境失败与产品缺陷分开，未运行、未验证明确标出。
4. 对照每项验收要求核对行为证据与规格、质量两项结论，检查实际 diff/write-set 和集成后的组合行为。两项结论不要求两名审查者，风险允许时可由 parent 自审并说明。实现者一句 DONE、绿色看板或清单勾选均不能独立证明完成；内容变化后核对受影响结论，不能沿用旧通过代表新内容。
5. parent 保存 result、evidence、method、pitfalls、outcome 及未解决事项，使用现有状态接口完成任务。研究假设被证伪且证据满足标准时以 rejected 完成；缺证据/中断保持真实未完成状态。达到约定验收且无阻塞问题后停止扩展，非必需建议不阻塞交付。

测试先行的任务保存有效 RED 与 GREEN；实现后补测只称回归检查。无需通过删除用户代码、篡改测试或伪造日志制造先失败的记录。

验收：面向结果使用者交付，简述结果、关键证据、未验证项和缺口；过程与内部审查材料按归档要求保留，不默认塞入主交付包。最终措辞与证据强度一致，例如“隔离初始化通过；真实 ZCode 派发未验证”。报告一项已验证事实不自动代表整个项目结束，项目完成必须覆盖全部目标与既定停止条件。

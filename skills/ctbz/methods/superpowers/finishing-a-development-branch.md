# 集成与收尾

先读 [共享契约](../contract.md)。仅 parent 决定并执行已授权的集成/记录/清理；子 Agent 返回其任务事实。

来源：Superpowers 6.3.0 `skills/finishing-a-development-branch/SKILL.md`。适配：沿用既有 Git 授权与 CTBZ ownership，保留全部过程证据；不强制重新选菜单、联网 pull 或删除工作区。

1. 按 [完成验证](verification-before-completion.md) 核对任务结果、实际 diff、评审绑定内容与未解决项，确认验收是否满足。有实质失败先修正或准确报告阻塞，不能把“实现结束”说成可集成。
2. 从任务契约与 Git 事实核对起点、目标分支、worktree 来源和用户已授权的提交/集成方式。已授权的本地提交、集成或发布按范围继续；尚未决定且现在必须决定时，父会话给出保留分支、本地集成或远端评审等实际可行选项并说明影响。
3. 父会话按依赖集成到明确的目标工作区，核对用户原改动与受审内容。冲突保留现场，只有在已确认语义与授权范围内能可靠解决才处理；不以 force push、重置或删除绕过失败。
4. 对集成后的实际内容运行相应组合验证，必要时更新评审快照并复审受影响接口。记录具体提交、测试、集成结果和剩余风险。未提交工作仍可完成用户任务并交付 diff，不能为了收尾自动 commit。
5. 保存报告、原始评审、修复理由、测试日志、方法/踩坑、负结果和接管历史。使用现有接口结束 run；项目目标全部验收后才单独确认项目完成。需要保留分支/工作区时给出准确位置。

## 清理条件

CTBZ 管理 worktree 仅由父会话按 [worktree 契约](../../references/worktrees.md) 调用 `node "<skill>/scripts/worktree" cleanup --manifest "<manifest>" --task-id <task>`，使用 manifest 中已持久化 ownership。只有已完成、已集成、验证通过、clean 且用户保留策略允许时请求清理；CLI 拒绝就保留并报告原因，不直接强删。

宿主或外来工作区由其所有者管理，不按目录名推断归属。所有 `.ctbz-record` 过程材料长期保留，即使分支已集成；用户明确要求丢弃时也先辨明实际范围与现有授权，不能顺带删除旁支或历史证据。

验收：交付位置与版本明确，集成后的证据可读，未验证宿主/外部行为准确标注；恢复会话能读到完成状态和原因，不重做已完成工作。

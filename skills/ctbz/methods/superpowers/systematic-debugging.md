# 系统调试

先读 [共享契约](../contract.md)。parent/debugger/tester 可在授权范围执行；explorer 只读定位调用链并返回证据，需运行/修改时交父会话。

来源：Superpowers 6.3.0 `skills/systematic-debugging/SKILL.md`。适配：保留根因调查、模式比较、假设验证和最小修复，合并本地技术参考；无上游 shell/npm 脚本依赖。

## 四步调查

1. **建立复现与根因线索**：读完整错误、堆栈、路径和退出码；写清触发步骤、频率、输入与预期。比较最近改动和环境差异。沿数据流检查每个组件的输入、输出和状态边界，以最少且不含秘密的观测定位首次异常，使用 [追踪参考](../references/debugging-techniques.md)。复现不了就收集能区分原因的新数据，不凭猜测改代码。
2. **对比正常路径**：找同仓库能工作的相似路径，读其完整相关逻辑与依赖。列出失败和正常路径在参数、初始化顺序、状态、配置及资源生命周期的差别，逐项排除，不先认定某差别无关。
3. **一次验证一个假设**：写明“原因 X，因为证据 Y；若成立应观察 Z”，用最小、可撤回的检查验证。失败则保留负结果并更新假设，不连续堆叠无法归因的补丁。
4. **修复并证明**：根因明确后按 [TDD](test-driven-development.md) 建立目标失败检查，实现根因处的最小修正，检查其他调用者和受影响边界，再走 [完成验证](verification-before-completion.md)。必要的防护加在真实信任/副作用边界，不为每一层机械复制校验。

## 无进展与环境问题

连续尝试无新增证据、修一处坏另一处、需要超出 write-set 或发现架构前提不成立时，停止堆叠修复，向父会话报告已试假设、命令结果与需要调整的范围。父会话在实际预算内决定补资料、缩小任务或修订计划；模型更强不代表根因已经找到。

调查证明是外部、时序或环境约束时，记录证据与影响，按授权加入恰当超时/重试/错误提示。等待真实完成条件而非任意加长 sleep；没有根因证据时明确尚未定位，不把防御性补丁称作修复。

验收：能解释原始异常为什么发生、具体修正怎样阻止它，以及哪些验证已运行。研究中否定一个假设也是证据，尚未执行的检查不是负结果。

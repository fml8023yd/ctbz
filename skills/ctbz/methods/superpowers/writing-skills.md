# 编写与验证运行方法

先读 [共享契约](../contract.md)。parent 维护目标、调度与记录；implementer 在写集合内编辑，tester 验证，reviewer 只读返回评审。

来源：Superpowers 6.3.0 `skills/writing-skills/SKILL.md` 及技能测试参考。适配：可观察消费场景、按需文档和本地依赖闭包；不自行调用模型、重复计费、安装 Graphviz、全局部署或新建可发现嵌套技能。

1. 确认值得固化的是重复出现的判断/步骤/资源需求，而非一次任务日记或已有工具能确定校验的规则。读取现有入口与调用者，明确触发条件、角色、输入、产物和真实已观察问题。
2. 在改文档前保存针对问题的场景或已有失败证据，选择行为约束、步骤技巧、选择模式或资料检索对应的验证方式。没有真实基线运行就说明未取得，不伪称已经观察 Agent 失败。
3. 写最小可执行说明：触发边界、先读材料、准确步骤、失败处理、输出与验收。遗漏字段用结构化模板补，判断条件写成明确分支，错误输出形状用正向示例说明；不要用越来越多“永远必须”替代具体条件。
4. CTBZ 包只有根 SKILL.md 是发现入口，方法是索引注册的普通 Markdown，无独立 frontmatter。共享规则链接 [契约](../contract.md)，重复模板放包内资源；对每个本地链接和命令核实文件、工具与权限，source-only 原件不参与运行。用户项目中的其他技能遵循其实际安装与授权范围。
5. 按 [前向场景](../references/skill-scenarios.md) 检查消费效果，并由父会话安排已有授权内必要的独立验证。禁止子 Agent 时做父会话走读并标注限制。根据实际失败窄幅修正，检查已通过的场景是否回归，再将变更交既定发布流程。

## 验证与发布边界

静态检查能证明索引、路径、哈希与资源可达，不能证明宿主真实发现、角色加载或模型行为。文字包含某句话也不能证明执行遵守。需要多次模型采样时由父会话按实际授权和预算安排，没有更高档模型或计费授权不会触发隐式升级。

默认文档用 Markdown 表格或文本解释流程，不执行归档中的 `render-graphs.js`、Graphviz 或视觉服务。原件中的最佳实践、说服原理和压力测试案例保留为 source-only 参考；运行材料已包含本方法所需步骤。

验收：新消费者能找到方法、执行授权内步骤并产出可核对结果；入口范围准确、支持文件闭合、角色不扩权、记录不分叉。提交/安装/发布按任务已有授权处理，不因编写技能自动 push 或覆盖个人安装。

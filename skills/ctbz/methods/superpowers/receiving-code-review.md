# 接收与落实评审

先读 [共享契约](../contract.md)。parent 维护决定和记录；implementer/debugger/tester 在任务 write-set 内落实具体修复，不另派 reviewer。

来源：Superpowers 6.3.0 `skills/receiving-code-review/SKILL.md`。适配：技术事实优先、疑点集中回父会话，独立已授权修复可继续；不自动向外部评审系统发送消息。

1. 读完整评审或用户纠偏及其对应内容，把每项要求还原成具体触发、影响和期望行为，检查是否仍对应当前版本。先核实事实，不因措辞有信心就附和、认错、修改或重跑全部流程。
2. 对照当前实现、调用者、平台兼容与已确认业务决定，验证问题是否成立。成立时明确失效假设、受影响产物/版本及作废结论；尚无证据时标为待核实。新增功能、抽象或治理只有属于当前目标必需项才实施，其余保留建议，不以“更专业”为由扩大目标。
3. 逐项形成 `accept`、`dispute`、`needs-evidence` 或 `needs-decision` 的事实与依据。相关疑点一次交父会话集中处理；与疑点独立的明确授权修复可继续。与用户口径、范围、费用或验收冲突时，保存可审查材料后由父会话处理，不能悄悄改规格。
4. 优先修复阻断功能/验收的问题，再处理其余本次必要项。每项或紧密相关的一组做最小根因修正，重验受影响行为与依赖，保留未失效的证据；记录原 finding、失效范围、改动、测试和未解决项，父会话保存新报告和快照。
5. 父会话按风险安排针对原问题与修复差异的复审。明确误报可以用文件和行为证据驳回，保留原意见及理由；真实重要缺陷不能因达到重试上限自动豁免。连续尝试没有新增证据时换诊断路径，预算耗尽如实阻塞依赖并保存下一步；达到验收且无阻塞问题后停止扩展。

输出采用事实：“位置 X 在条件 Y 下会 Z；已通过检查 A 修正”，或“该建议会破坏兼容 B，依据 C，保留当前实现”。无需先赞同，发现自己判断错误时简述更正和新证据。

验收：每项评审有可追踪处置，实际修复有当前内容的验证和复审，未解决风险仍可见。

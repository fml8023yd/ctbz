# 根因追踪与稳定验证

先读 [共享契约](../contract.md)。改编自 Superpowers `skills/systematic-debugging/{root-cause-tracing,defense-in-depth,condition-based-waiting}.md`。只读角色提出调查与测试方案，授权执行角色落实。

## 从症状追到入口

记录完整错误、触发操作、实际与预期值。从失败点找到直接调用者及传入值，逐层向上定位首次违反约束的位置，再检查该入口的其他调用路径。例：错误目录中出现文件，追踪 `cwd` 的来源、空值回退、初始化时机及路径规范化；在错误值产生处修正，不能只在报错点加默认值掩盖。

静态阅读不能定位时，只加能区分假设的临时观测：组件输入/输出的形状、执行顺序、状态或错误码。日志不含凭据、业务数据或完整环境变量。保留关键证据到父会话报告，删除无用临时观测。真实外部系统不可擅自操作，优先隔离复现。

## 测试污染

先确认单测独立运行是否通过、按原顺序组合是否失败。用项目已有测试过滤器把前序测试分成两组，在同样的临时目录与初始状态重跑；逐步缩小污染来源，再检查未清理的文件、全局变量、环境、时钟或连接。不要删除用户工作区求得干净状态。缺少过滤器时由 tester 在临时副本按测试清单逐项运行，记录命令与状态。

上游 `find-polluter.sh`、npm 假设和示例程序仅随原件归档；本方法不调用它们，也不安装测试工具。

## 按边界防护

列出不可信入口、领域约束、危险外部操作和诊断点。针对确实存在的绕过路径增加相应防护，并验证异常会在副作用前拒绝。复用已有校验，不在每个函数重复同一检查，不声称加上四层就能证明永远不再出错。路径检查按解析后的目录边界判断，避免仅用字符串前缀。

## 等条件，不猜时间

优先等待已有完成事件、Promise 或测试框架提供的条件等待。必须轮询时，每次读取新状态，设置实际任务需要的轮询间隔、截止时间和取消出口；超时报告等待的条件与最后观测。先等到操作已开始，再测 debounce、节拍等真实时间行为。固定延迟只在时间本身是验收对象时使用，说明依据。

验证异步代码时覆盖未完成、成功、超时和取消/失败；不要仅把 sleep 增大到当前机器碰巧通过。

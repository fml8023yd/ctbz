# 编写能发现错误的测试

先读 [共享契约](../contract.md)。改编自 Superpowers `skills/test-driven-development/writing-good-tests.md`。

写测试前说清：哪一种真实错误会使它失败，并把影响结果的关键约束落实为检查。按任务核对版本、字段集合、关联键、样本粒度、时间边界、标签或输出值；可确定、可重复的检查优先脚本化。预期值由需求、手工核对的样本或独立来源推导，不调用被测函数或其同一构造器算 expected。验证对外结果、参数契约、状态变更和副作用，不锁死无关的源码措辞、私有结构或刻意选定的常量。

运行真实组件和真实分支。外部、慢或有不可逆副作用的依赖才用隔离替身，并先理解被替换操作的副作用，保留本次验收依赖的行为。必要的调用次数/顺序/参数是业务契约时可以断言；只证明 mock 存在的断言没有价值。替身要覆盖完整实际响应结构以及失败形态。

测试专用清理代码放在测试工具中，不向生产类添加仅测试使用的 API。复杂 mock 比实际集成测试更难理解时，用临时目录、内存或已有本地组件验证边界。无需为本方法新增框架、联网安装或调用真实收费服务。

检查至少一个正常行为与本次风险相关的空值、错误输入、权限、并发或恢复边界。设想删除校验、反转分支、丢失副作用、返回空结果，已有测试应能发现相关缺陷。不要为达到覆盖率为所有 getter 或文案逐一配测试。

批量处理与语义判断先检查正例、反例及不确定情形，再扩展执行；说明不确定项如何保留或交回复核。样例用于发现判定规则的问题，必要的全量检查仍覆盖全部对象，例如键唯一性、字段齐全、时间边界及输出总量。分别记录样例与全量覆盖范围；替代检查标明无法证明的原要求，不能冒充原验收通过。

脚本用控制输入验证输出、退出码与副作用；运行方法文档用真实消费场景验证判断，字符串搜索只负责路径、格式和资源静态检查。人类说明的纯措辞修改不需要代码测试。纠偏或内容变化后重验受影响的行为与依赖；保留仍有效的证据，必要检查通过且无阻塞问题时停止重复测试，残余限制如实说明。

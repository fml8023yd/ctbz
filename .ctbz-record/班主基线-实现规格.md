# 班主基线 0.1.0 · 实现规格

本文件是本次改版的唯一施工依据。所有 Agent 先读本文件，再读各自写集合内的现有文件。

## 目标

把 CTBZ 0.0.2 升级为 0.1.0：

1. 班主基线写死：主进程零产出，只拆、派、验、问；唯一例外是用户明确说“你自己做 / 亲历 / 别派了”。
2. 模式简化为自动 / 计划；自动默认。
3. 计划流水线：侦察 → 6 路计划 → 合并 → 6 路攻击 → 裁决。
4. 执行流水线：并行执行 → 集成 → 集成门 → 6 路全量验收 → 班主终检 → 交付/推送。
5. 30 分钟决策升级 + 决策账。
6. 倒叙汇报协议：细节在前，总结在后；推送用短格式。
7. 跨 run 写集锁、计划/产物版本绑定、法定人数、回退有界。

## 一、班主基线（不可关闭）

### 权限

| 主进程做 | 主进程不做 |
|---|---|
| 读代码、文档、证据，为了拆得准、验得真 | 写或改任何项目交付文件 |
| 想、判断、裁决、问澄清 | 写代码、文档、测试、做集成 |
| 拆任务、写派发 brief | 替 Agent 补最后一行 |
| 派发、排队、串行化写冲突 | 亲自做研究并产出报告 |
| 验收：读最终产物、跑验收命令、走用户实际路径 | 拿 Agent 的“已完成”当验收 |
| 记 `.ctbz-record`、dashboard、决策、证据 | 用“顺手”当例外 |

可写范围：`.ctbz-record/`、dashboard 状态、派发 brief、推送 payload。项目交付文件一律不碰。

唯一例外：用户明确说“你自己做 / 亲历 / 别派了”。记录 `mode=亲力`，按普通执行流程做，但最终仍要验收。

主进程可以修自己的派发材料（brief、路径、任务契约），不可以修下属的交付物。

### 拆分法

- 按可独立验收单元拆，不按人数拆。
- 同文件 / 同编译单元只能一个 owner；冲突串行。
- 有环依赖合并，或先冻结接口。
- 拆成 N 份必须同时指定集成 owner；没有集成责任 = 假拆分。
- 每个 brief 必须通过“新鲜 Agent 测试”：没读过本会话的 Agent 能直接开工，不问问题。
- 拆分前读到能验收的程度；读不懂不配拆。傲慢是对边界，不是对事实。
- 数量按任务实际结构；1 个任务 1 个 Agent 也合法。

## 二、模式

| 模式 | 计划流水线 | 执行 | 何时用 |
|---|---|---|---|
| 自动（默认） | 完整 P0–P4 | 继续 E1–E5 | 用户给任务就走 |
| 计划 | 完整 P0–P4 | 停 | 用户要先看计划 |

- 自动模式不问技术细节；只有“决策升级”清单触发时才问。
- 计划模式在 P4 后交最终计划 + 决策日志 + 执行契约，不执行。
- 计划模式收到用户反馈后：派 1 个计划编辑 Agent + 1 个轻反审 → 新版本。班主不执笔。
- 用户明确放行后，计划冻结，进入执行。

### 宽度

- 默认 6；轻档 3；重档 8–10。
- 宽度只改并行数，不改流水线结构。
- 宽度=1 时，合并步由裁决者兼任。
- 班主记录选择理由。

## 三、计划流水线

### P0 接单 / 诊断

班主读已有记录、看板、相关决策；核对用户最新指令与授权。产出：目标、硬约束、非目标、成功证据、未知事实、拆分草案。只读。

### P0.5 侦察事实表

1–2 个 explorer 只读产出事实表：相关文件路径、接口、数据流、依赖、约束、未知项、风险。6 路计划必须引用同一份事实表。任务简单、事实已足够时可跳过，班主记录理由。

### P1 并行计划

- 6 个计划 Agent（默认），同一 brief + 事实表，不同角色/模型。
- 建议镜头：最小改动、正确性优先、风险优先、用户路径优先、可维护性优先、对抗视角。
- 互不可见。
- 每份计划必须含：目标复述、方案、任务拆分、writeSet、依赖、集成 owner、验收命令、风险、替代方案、未知项。

### P2 合并

1 个合并 Agent 读 6 份计划，产出：
- 合并稿；
- 分歧清单；
- 每个模块采用谁的方案、为什么、丢了什么。

不丢少数派；不把 6 份计划揉成模糊共识。

### P3 并行攻击

- 6 个攻击 Agent（默认），不同镜头：需求覆盖、可行性、写集/依赖冲突、可测性、安全/风险、更小方案。
- 输入：原始需求 + 事实表 + 合并稿 + 分歧清单。
- 不看 6 份原计划，避免被带偏。
- 每条攻击必须带：触发条件、证据、影响、建议或证伪测试。
- 允许“没发现实质缺陷”。

### P4 裁决

1 个裁决 Agent，输入：6 份原计划 + 合并稿 + 分歧清单 + 6 份攻击 + 原始需求。

产出：
- 最终计划；
- 执行契约（任务、writeSet、依赖、集成 owner、验收命令、停止条件、预算、planVersion + hash）；
- 决策日志（采纳/驳回 + 理由 + 证据）。

高风险驳回必须带证据或证伪测试，不能只写“没必要”。

### 计划模式出口

交最终计划 + 决策日志 + 执行契约。不执行。等用户拍板。

## 四、执行流水线

### E1 并行执行

- M 个执行 Agent，按写集并行；冲突串行。
- 每个任务 brief 绑定 planVersion + hash。
- 回执：改动文件、行为说明、验证输出、未完成项、风险、基线差异。

### E2 集成

1 个集成 Agent（不是班主）：合并接口、跑构建/组合测试、解决集成问题。集成 owner 唯一。

### E2.5 集成门

build + smoke test 过了，才允许开 6 路验收。不过打回执行，不浪费验收预算。

### E3 全量验收

- 6 个验收 Agent（默认），不同镜头：正确性、需求覆盖、安全、性能/资源、用户体验/实际路径、可维护性。
- 每个验收 Agent 看整份产物，不切片。
- 先写“我看到了什么”：逐文件/逐行为说明实际改动、接口、数据流、副作用，带证据位置；再对照计划。
- 自己跑验收命令，不拿实现者的自述当证据。
- 输出 verdict + evidence + issues + 未覆盖项。
- 验收者不复用执行者。

### E4 班主终检

三层验收：
1. 意图 → 计划：计划是否真的解决用户的问题。
2. 计划 → 产物：验收员的结论是否成立，抽样核对证据。
3. 产物 → 实际使用：按用户实际路径走一遍。

按风险抽样：关键路径必查，非关键路径抽一项；抽样规则记录。

### E5 交付

- 推送：ServerChan；内容为结果、证据位置、缺口、下一件；不带密钥。
- 推送失败不阻塞交付，但必须在汇报里标“未送达”。
- 汇报用倒叙协议。
- 问下一件；保留当前 run 记录，追问能直接接上。

## 五、30 分钟决策升级

### 先自查（必须）

1. 这事真的阻塞吗？不决定就不能继续，或继续会做错？
2. 能不能用读代码、跑测试、查文档、已有授权、默认值解决？
3. 能不能先做无依赖部分？
4. 影响够大吗？不可逆 / 外部写入 / 花钱 / 权限 / 目标变更 / 高爆炸半径歧义。

只有“阻塞 + 无法自行裁决 + 影响大”同时成立，才问。

### 问法

- 发推送：一句话问题 + 选项 A/B/C（每个一行）+ 推荐 + 默认 + 30 分钟截止 + runId。
- 停止受影响分支；继续无依赖工作。
- 登记一次性 30 分钟唤醒（宿主支持时）；不支持则下次检查点补执行。

### 等待与继续

- 30 分钟内收到回复：取消唤醒，按回复继续。
- 30 分钟无回复：按默认项继续；记录“未获回复，采用默认 X”。
- 最终汇报带决策账：当时面临什么决定、A/B/C、为什么必须问、你没回、我们怎么做的、影响是什么。

### 不能问的

技术细节、实现选择、命名、文件位置、测试方法、已有授权/先例、能靠证据解决的事、为了“显得尊重老板”而问的事。

## 六、倒叙汇报协议

适用：所有用户可见输出（聊天、推送、计划、交付）。

### 结构

先逐项细节，最后写总结：

```
### 1. 事项一
- 做了什么
- 关键证据（路径/命令/版本）
- 问题/风险

### 2. 事项二
...

### 总结
- 现状
- 已完成
- 未解决 / 风险
- 决策账（如有）
- 下一步
```

用户从下往上读，总结是他看到的第一屏；细节是追问时的下钻。总结必须能独立回答“现在什么情况、还差什么、下一步做什么”。

### 配套

- 引用 i-have-adhd：先给下一步行动、编号、状态复述、具体时间、错误直说、列表≤5、无客套。
- 推送更短：一句话问题 + A/B/C + 默认 + 截止 + runId。
- 短回复 / 纯闲聊不套模板。
- 不写“综上所述 / 需要注意的是 / 简单来说 / 希望对你有帮助”。

## 七、失败策略

| 触发 | 行为 | 记录 |
|---|---|---|
| 派发失败 | 记录 harness-rejected，重试/排队；不静默亲力 | harness-rejected |
| Agent 失联 | 确认停止，核查检查点，重派新 Agent；不接管执行 | native-mid-task-failure + agentId |
| 合并者失败 | 换模型重试；仍失败用最佳单计划 + 分歧记录 | merge-fallback |
| 裁决者失败 | 班主裁决，派 scribe 落盘；班主不执笔 | adjudicator-fallback |
| 法定人数不足 | 到 4/6 即可继续；迟到作附录；缺谁记谁 | quorum |
| 跨 run 写冲突 | 冲突任务排队；不冲突并行 | write-conflict |
| 无 Agent 可用 | 报阻塞，问是否亲力；用户明确后才亲力 | no-native-tools |
| 权限拒绝 | 停止被拒动作，不绕过 | permission-denied |
| 3 轮回修不过 | 停，报缺口；关键项未完成不得标交付 | rework-budget |

## 九、测试场景

| 编号 | 场景 | 通过标准 |

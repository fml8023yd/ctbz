# CTBZ 0.2.1 · 失败内审即时化 + Kimi → swe2 迁移

## 背景

1. reviewer 失败时主进程等整批结束才发现，浪费一轮。需要失败即时触发内审：记录错误、禁用该 Agent、立刻重派。
2. 所有 kimi 模型的子代理换成 swe2。

## 任务一：失败内审即时化

### 规则（要落到核心文档）

在 `班主基线.md` 失败策略和 `自动模式.md` 执行流水线里加：

- 任一 Agent 回执为失败/失联/权限拒绝/无证据完成时，班主**不等整批结束**：
  1. 记录该 Agent 的失败到 `.ctbz-record/runs/<runId>/audit-<taskId>-<agentId>.md`；
  2. 在任务级禁用该 Agent（同一 run 内不再派发同一身份）；
  3. 立刻按原 brief 重派新 Agent（不同 model/profile 优先）；
  4. 其余在途 Agent 不受影响继续跑；不阻塞合并/攻击/验收。

- 只有确认旧 Agent 已停止后才允许重派写同一 writeSet 的任务；未确认停止按 `awaiting-stop` 处理。
- 权限拒绝不重派，报 `permission-denied`；模型失败/断流重派；连续 2 次同任务失败升级班主裁决。
- 失败的 Agent 记录保留，供 E4 班主终检和质疑预演引用。

### 代码级（native-runtime.mjs）

目前 `run` 是等待 `port.wait` 后返回终态。要支持“即时失败”：

- 端口可选实现 `onEvent` / `onReceipt`：收到终态即回调，不等全部 batch。
- `run` 在收到终态后立即进入失败分支（emit 记录、可选禁用、重派），不再把失败留到调用方统一处理。
- `createRuntime` 增加 `onTaskFailure` 回调参数，供父会话在失败发生时就登记禁用与重派。
- 保持现有 API 向后兼容；默认行为不变（无 onTaskFailure 则维持现状）。

## 任务二：Kimi → swe2 迁移

### 目标

把 `~/.zcode/agents/` 下所有 `team-ctbz-*-kimi-k2.8-enabled` profile 换成 swe2。当前 kimi profile 8 个：debugger/explorer/implementer/planner/reporter/researcher/reviewer/tester。

### 做法

1. 不删旧 kimi profile，先改名备份到 `~/.zcode/agent-backups/kimi-replaced-<timestamp>/`。
2. 生成 `team-ctbz-<role>-swe2-enabled.md`，模型引用 `custom:new-provider:swe-2`，thoughtLevel 沿用 enabled。
3. 每个角色保持原有 tools；leader 不参与（leader 无 kimi 版本，只有 deepseek/hy3）。
4. 更新 `~/.zcode/agents/` 后，新会话的 Agent 类型列表才会出现 swe2 profile；本 session 的工具列表不会热更新。
5. `adapters/zcode/scripts/lib/初始化.mjs` 的 profile 生成规则里如有模型名映射，补 swe2 映射（若不存在则记录为后续）。
6. `skills/ctbz/cost-rules.json` 的 `role_tier` 与模型无关，不用动；`vendor_map`/`model_health` 若含 kimi 映射需核对。

### 验证

- `ls ~/.zcode/agents/ | grep swe2` 有 8 个 profile。
- `grep -l "kimi-k2.8" ~/.zcode/agents/team-ctbz-*` 应为 0（旧文件已备份）。
- 新会话 Agent 类型列表包含 `team-ctbz-*-swe2-enabled`；当前 session 仍看到 kimi 属正常。

## 一、重构模式（十步定稿，用户九条 + 反审修正）

触发：用户点名"重构模式"（随口"重构一下 X"按普通任务路由，AI 视量级建议升级）。【自动重构】进命令集登记。

1. **确认重构边界**（范围/非目标/成功标准）
2. **理清逻辑**（不止行为清单）：产物=【现状行为清单】（每条含【层级】外部契约|可观测副作用|实现细节、【发现来源】静态读码文件:行|实证、【处置】必须保留|允许变更+理由）+ **意图与历史动因笔记**（防止删掉有意为之的逻辑）。落盘 `.ctbz-record/methods/<node>/<run>/<task>/behavior-inventory.md`
2.5 **基线固化**：对【必须保留】行为用旧实现跑出输入→输出/副作用快照（golden），落 `.ctbz-record/.../baseline/`；旧模块无测试时按"必须保留"条数逐条补最少量测试，不全量补测；判定为【允许变更】的副作用（日志等）剔除出等价范围
3. **新方案设计**：服务整个项目（用户原表述保留）+ 连接上下游（附加要求）；以行为清单为对照
4. **反审**：主对象=方案质量（遗漏/冗余/是否真服务整个项目）；增补视角拆两指标——清单自洽率（reviewer 可判）/ 清单完备性（步骤 2 作者+基线证据负责，reviewer 只做抽样反例挑战）；反审输出="对【必须保留】条目的反例清单"，覆盖率 100% 硬门取消
5. **表达 + 叫停窗口**：表达=最后一次廉价叫停点；自动重构经 ServerChan 推送一次"方案已表达，N 分钟后开干，回消息即暂停"（扩 1.7.0 推送条款语义）
6. **派发**：同模块重构=单 Agent 单 worktree 单 write-set；≤5 并行仅适用于已物理拆分的可独立编译单元，单元接口定义与实现同 write-set、不共享文件；写并发守 maxParallelWriters
6.5 **集成**：备份旧模块（原文件副本或 tag）→ 原子替换 → 失败/等价性验证失败回退到备份，汇报明示"已回退/已替换"
7. **行为对照验证**：【必须保留】条目逐条 vs 基线快照，可判定可脚本化
8. **停机条款**：发现超边界行为（暗藏依赖/隐含副作用）→ 该模块置待确认落盘（manifest+dashboard）、自动模式 ServerChan 推送、不等待、其余继续；dirty worktree 保留
9. **汇报**：行为清单对照结果 + 留删清单（删除需用户授权）

## 二、settings.yaml 用户偏好体系

路径：`~/Documents/.ctbz/setting.yaml`（用户级跨版本；数据按版本目录、偏好跨版本）

```yaml
版本: 1.8.0
权限边界:
  执行档位: 标准            # 标准 | 自动默认开 | 谨慎（计划必确认）
  计划超时自动执行: 30分钟   # 0=关；>0=倒计时默认档（回滚锚点先行+到点 ServerChan 推送提醒）
  可写目录: []
触点:
  serverchan_key_env: SERVERCHAN_SENDKEY   # 存环境变量名不存 key 值
  推送开关: true
知识库:
  自动沉淀: true
  待批提醒: true
继承来源: ""
```

- **初始化访谈+继承**：首次"草台班子"或 dashboard init 时访谈（权限边界/触点/知识库偏好）；先扫旧版本 settings 与环境变量（SERVERCHAN_SENDKEY 存在即自动带出）→ 只问变化项与新增项；写盘时记录继承来源
- **ServerChan key 双保险**：settings 只存环境变量名，key 本体在环境/钥匙串
- **1.7.0 推送条款改读 settings**（不再临时检查）
- **计划超时自动执行档位**：settings 配置 >0 时，计划给出+到点无叫停 → ServerChan 推送提醒 → 回滚锚点先行 → 执行（1.7.0 限时授权语义的全局默认化）

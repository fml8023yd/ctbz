# 版本升级=能力盘点 提案（20260916）

- 背景：2.0.1 带了 自动更新检查.mjs 进仓库，但无人挂定时任务——脚本生效≠功能生效，中间的"本机挂载"环节无人负责，直到用户追问才补上。
- 根因：部署/初始化流程没有"读新版 CHANGELOG、盘点新增能力"的步骤。
- 处理：本提案交负责 ctbz 更新的 Agent 走正式流程（反审→发版）落地，下个版本带上。

## 改动 1：SKILL.md 新增条款（部署节或初始化节附近）

```
**版本升级=能力盘点**：部署新版本后，必须读该版本 CHANGELOG/git diff，盘点新增脚本与
功能；凡需本机挂载才能生效的（定时任务/本地服务/新配置项/provider），当场激活或列
"待激活清单"报告用户，不得静默略过。盘点结果一条行记入 .ctbz-record/记录.md
（格式：版本→新增N项→已激活X/待激活Y）。
```

## 改动 2：自动更新检查.mjs 补挂载自检（可选增强）

脚本尾部更新成功分支追加输出 `pendingHooks` 字段：
- 扫描 skills/ctbz/scripts/ 下带 `定时`/`cron`/`schedule` 注释头的脚本
- 与 ~/.zcode 宿主已注册定时任务比对（读 automation 标题清单）
- 输出 `{updated:true, pendingHooks:["自动更新检查"]}` 供会话层决定挂载

## 改动 3：CHANGELOG 模板加一节

发版.sh 生成的 Release notes 模板固定含：

```
### 本机挂载项
• <需手工/会话激活的能力清单，无则写"无">
```

——让"盘点"在每个版本的发布面与部署面双向可见。

## 验收

1. 模拟部署一个带新定时脚本的版本 → 盘点输出含待激活项
2. 真实场景回归：2.0.x 正常部署不受影响
3. CHANGELOG 新版含"本机挂载项"节

# CTBZ 发布清单

> 唯一发布源：仓库 `源码/skills/ctbz/`。`ctbz-pack*`、历史压缩包与评估截图仅作归档，不得作为发布输入。

## 发布前

- [ ] 在仓库根目录确认 `git status`，核对待发布变更均来自 `源码/`。
- [ ] 执行 `node 源码/skills/ctbz/scripts/发布检查.js <安装副本>/`；lock、依赖校验、入口冒烟必须通过。
- [ ] 搜索退役路径和旧版本命令：`rg -n 'ctbz-pack|1\\.[0-8]\\.|旧模型路由' 源码/docs 源码/skills/ctbz`，命中项须说明为历史记录或修订。
- [ ] 确认 `CHANGELOG.md` 已记录版本、迁移提示和已知限制。
- [ ] 从干净安装副本运行 `initialize status` 与关键测试。

## 打包与发布

- [ ] 仅从当前 git 提交生成包；包名包含版本和日期。
- [ ] 包内不包含 `.git`、`.ctbz-record`、评估截图、临时日志和历史包目录。
- [ ] 发布后用包内 `dependencies.lock.json` 再跑一次 `verifyBundle`。
- [ ] 记录提交 SHA、包 SHA256、安装路径，作为可追溯证据。

## 历史归档

历史包、截图和旧架构图保留在原位置，不参与运行时发现、依赖锁定或发布打包。需要引用时标明“历史归档”，避免被误当作当前版本。

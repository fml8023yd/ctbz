## 1 需求诊断

| 项 | 内容 |
|---|---|
| 原始表述 | 用户：「在 ctbz 下的『任何』一步行动，是否都能经得起质疑」 |
| 真实问题 | 2.1.0 取证闸只覆盖「说出来的数」（断言）；**「做出来的事」无载体** —— 定规则、改文件、跑命令、选路径、下结论都不需交代「凭什么」与「什么会推翻它」 |
| 目标结果 | 任何一步行动 = **事前入账**（计划 `## 行动账`）或 **事后入账**（复命 `行动账增量:`），二者必居其一；每行四列。**覆盖口径＝计划内动作＋计划外动作；反审席位自身、纯只读探查、对话中即时裁决、部署发版为已知缺口（§6）** |
| 非目标 | 不判「依据是否充分」「取舍是否高明」；不追溯 2.0.x–2.1.0 历史动作 |
| 成功证据 | V1–V7（§5） |
| 意图置信度 | 高 |

## 3 冻结文本

### 3.1 `SKILL.md` 新增一节（插在 `## 自证与自疑（交付前必跑）` 整节**之后**、`## 统一模式规则` 之前）

```markdown
## 行动可质疑性（任何一步都要能交代）

**不追求不可推翻，追求可追溯、可推翻、推翻后能定位。**

| # | 规则 |
|---|---|
| 1 | 任何一步行动，要么**事前入账**（计划的 `## 行动账`），要么**事后入账**（复命清单的 `行动账增量:`）；二者必居其一 |
| 2 | 每行四列：`动作`｜`依据`（`文件:行号`／命令／以「」包裹的用户原话）｜`取舍`（须含被否候选与理由）｜`证伪`（可执行：命中 `exit 0-2`／`pass N`／`N fail`／`路径:行号`） |
| 3 | 「依据」列的 `文件:行号` 按取证闸校验；「取舍」列**整值等于**空话词表任一项即判红（`无｜N/A｜—｜显而易见｜常规做法｜最佳实践｜一般来说｜通常`） |
| 4 | 推翻后能定位：任一步被推翻时，其所在行号即回修起点；不得只改结论不改依据 |

账行写法：`| A<n> | 动作 | 依据 | 取舍 | 证伪 |`；列内含竖线须写成 `\|`。
```

```js
const LEDGER_HEAD = /^##\s*行动账\s*$/m;
const LEDGER_EMPTY_WORDS = ["无", "N/A", "—", "显而易见", "常规做法", "最佳实践", "一般来说", "通常"];
const LEDGER_DENY_RE = /否掉|弃|排除|不采用|而非|放弃|改为/;
const LEDGER_FALSIFY_RE = /exit\s*[0-2]\b|pass\s*\d+|\d+\s*fail|[A-Za-z0-9_./\u4e00-\u9fff-]+\.(?:mjs|js|sh|md|json):\d+/;
```

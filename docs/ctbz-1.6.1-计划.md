# ctbz v1.6.1 计划（知识库体系 + 体验改进）

- 基线：1.6.0（git tag，引擎树合并版）
- 版本权威：以 git 为准；本机 1.6.1-dev → 推送后 v1.6.1

## 改动 1：构建知识库（新入口）

- 触发：`草台班子 构建知识库`（也认"初始化知识库"）；幂等（已存在报现状不重建）。
- 冷启动产物（`~/Documents/.ctbz/{版本号}/知识库/`）：

```
常用.md            ← 预置"知识库使用法"速查（首条元知识，零污染种子）
目录.md            ← 每条一行：标题（触发：词1|词2）→ 分区文件#锚点
建模.md / 业务.md / 数据.md / 案例.md   ← 空骨架，头部带本类收录标准
待批区/            ← 每条一文件（流水特性）
自记库-YYYY-MM.md  ← 月度单文件（低信任草稿）
```

- 不批量导 Betty 旧知识；种子只放一条示范（PC/分期标签默认规则）。

## 改动 2：存储与检索协议

- 存储四规则：单文件单类 ≤60 行；常用.md=热缓存 20~30 条（晋升/退潮机制：目录命中 3 次+升格，超 30 条退最冷）；检索漏斗=常用→目录触发词交集→锚点精读→待批/自记；增删改路径（分区文件原文为准，常用行同步）。
- 读点协议：**先分析任务原文识别知识空白→带缺口定向查**（不通读）。三个读点：①讨论前（词典型 30 秒）；②执行中遇字段/路径（事实型）；③完成反审（写）。strict 派发时主进程把命中条目写进子 Agent 契约，子 Agent 不自进库。读超 3 个全文=库的病，记意见箱。
- 条目格式：触发词/类型/scope(通用|本机)/有效期/需现场核验/⚠易错点。坏知识一等公民，命中优先浮出。

## 改动 3：意见箱修正

- 路径：`~/Documents/.ctbz/{版本号}/意见箱/意见-YYYY-MM.md`（原 Documents/意见箱 迁移后删除）。
- 反馈模板：`收到您的意见【原文】\n已记录到意见箱 [目录] 中\n【时间】【草台班子 版本】【记录性质：仅记录未采纳】【原文】`（完整复述条目）。
- 脚本 `scripts/意见箱.py` 路径参数化+输出目录。

## 改动 4：初始化版本检查

- `dashboard init` 读现有 `.ctbz-record/dashboard.json`：无→正常初始化记 version；有且 version < 当前→提示"新版本新能力（列差异），是否迁移/重建"，不静默。
- 意见箱跨版本割裂由检查补：初始化时提示旧版本目录下有 N 条意见，搬不搬用户定。

## 改动 5：文字经济学（已入主文件）

- 主进程服务姿态第 4 条：用户注意力最高成本；结论先行、表格优先、细节落盘、聊天一行状态；内部详尽对外吝啬。

## 冲突闭环（知识库 vs 现场）

Agent 自查（用错/过期/前提变化）→ 查不出才问用户（每冲突点限一次）→ 裁定回写（正式库更正/自记库纠正/标过期）。

## 验证方案

- 构建知识库实测（目录结构+预置内容+幂等）；检索漏斗实测（沙盘任务：PC老客模型→命中建模.md 条目）；意见箱新路径+复述模板实测；版本检查实测（伪造旧 version）；pick-profile 回归（确保无回归）。
- 脱敏审计：新文件无绝对路径/密钥。

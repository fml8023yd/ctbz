# 提案：轨道与边界（待讨论）

提出：2026-09-22｜来源：用户「我给你构建一个边界，边界之内你像神经元里的电信号，只需在节点间移动；常见任务有明确轨道，只在少数节点做『CVG 还是 PC』『新客还是老客』这类决策」
状态：**待讨论，未立项**｜关联待办：TD-13｜前置：TD-12（记忆与路由）

## 一、判断

| 类别 | 结论 | 依据 |
|---|---|---|
| 已知任务（高频 + 决策点封闭） | **是**，加速与标准化都成立 | 决策点收敛＝上下文预算从「重建世界模型」降为「判断局部」；查表比推理快且稳 |
| 未知任务（决策点不可穷举） | **不成立，且有害** | 硬把开放问题塞进二选一 → AI 假装确定（＝编造） |
| 无轨道检测 | 缺了它，整体变负收益 | 「一切顺利」与「轨道不存在、我在自由发挥」在信号内部**感觉一样** |

## 二、三条前提（缺一条即负收益）

| # | 前提 | 现状 |
|---|---|---|
| P1 | **无轨道检测**：任务开始先判「有无匹配轨道」；无 → 标「新任务」，转反审路径，不许假装在轨道上 | 无 |
| P2 | **腐化处理**：轨道节点带 `【有效期】`，命中即校验 | 知识库条目格式已有 `【有效期】`，协议已有「命中即查」，但**未被执行**（见 TD-12 R3） |
| P3 | **写回**：走完一次能把「这次在哪拐错/新增哪条岔路」补回节点 | 无 |

> 神经元类比需修正一处：真实突触权重可塑。若 AI 只是「不可写的信号」，本会话的教训（版本断言会被插入位移击穿、`exit=0` 会被判红）就无处沉淀。

## 三、形态建议（讨论用）

轨道 = 一份 `references/轨道/<活类型>.md`：

```
轨道：特征衍生交付
触发：特征开发|特征衍生|五件套|…
节点1 读    → 知识库 search "<原文>"；零命中 → 停，问用户限一次
节点2 分叉  → 产品线？ CVG / PC      （查 建模.md）
节点3 分叉  → 客群？   新客 / 老客    （查 is_new 口径）
节点4 产物  → 五件套（BTY-KNOW-4010）
节点5 校验  → 命名门禁(BTY-KNOW-4020) + 有效期检查
出轨条件    → 任一节点无匹配 → 标「新任务」转反审路径
```

每个节点四要素：**读什么 / 判什么 / 产物 / 失败怎么办**。这样可机械校验（节点有无产物、分叉选项是否封闭），也可写回（新增分叉）。

## 四、分层原则（一刀切会坏）

| 决策类型 | 判据 | 归属 |
|---|---|---|
| 事实型 | 选项可穷举、能查表 | **轨道**（CVG/PC、新客/老客、五件套…） |
| 判断型 | 选项不可穷举 | **反审**（四路多视角），不进轨道 |

反例：本会话三次改动（2.0.6 / 2.0.7 / 2.0.8）都不在既有轨道上，质量来源是**反审**（L1 四阵营逐轮挑错），不是轨道。**轨道负责「已知」，反审负责「未知」，二者不可互相替代。**

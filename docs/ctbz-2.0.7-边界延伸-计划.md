## 1 需求诊断

| 项 | 内容 |
|---|---|
| 原始表述 | 用户：「你不要什么事情都问我，我用 ai 是为了给自己省事的。你的边界能延伸的时候就去做」「只给我最原始的结果，或者只给我必须给我的东西」「探索以及所有子节点，我希望都可以在报告上看得到」 |
| 真实问题 | 「不确定就问」是比「做完再报」更省力的默认路径，且 skill 里没有任何条款拦它 → AI 把已有明确指令的下一步当「待裁决」上报，用用户的注意力替代自己的执行力 |
| 目标结果 | ①已写明的下一步默认做完 ②**复命前有机械闸**拦住「明明有指令却来问」 ③聊天少说、文档全留、自主延伸可见 |
| 非目标 | 不放松四扇门；不改 `~/.agents/skills/ctbz`（只经 `部署.js`）；不动其它脚本 |
| 成功证据 | V1–V6（§6），其中 V3/V4 为可重跑命令 |
| 意图置信度 | 高 |

### 2.1 `SKILL.md` 新节（插在 `## 反审硬门（1.8.2）` 整节**之后**、`## 统一模式规则` **之前**）

> 插入点在硬门行**之后**，硬门行位置不变；同时把 `tests/主文锚点.test.mjs` 的 V13 从「行号算术」改为「按内容定位」。

```markdown
## 边界延伸（做得多、说得少）

本节是**行为与交付口径**；输出格式仍以「哑巴模式」「末段契约」为准。冲突时优先级：四扇门 > 本节 > 输出格式条款。

**默认做**：同时满足三判据的动作，一律**做完再报**，不得作为「待裁决」上报。

| # | 判据 | 判法 |
|---|---|---|
| 1 | 有条款出处 | 能在本 skill / 计划 / 命令集 / 发布链里指出具体条款 |
| 2 | 可回滚或可验证 | 执行后能用一条命令回滚，或能用一条命令验证结果 |
| 3 | 不触四扇门 | 不涉平台写 / 凭据 / 真值 / 越权范围 |

例：部署、发版、出包、重算锁、探活、修自己发现的缺陷 —— 三条全满足 → 直接做。

**复命门槛（硬）**：交付前每个「待裁决」逐条自检——**出处指向本 skill 吗？指向 → 删掉该条，回去做**。机械版：`node <skill>/scripts/内审.mjs 复命 --file <复命.md>`，不过闸不得交付。

**问的唯一准入**（其余不占用户时间）。`准入:` 取值**逐字**只有三类，不得扩写：

| `准入:` 取值（逐字） | 含义 | 例 |
|---|---|---|
| `四扇门` | 平台写 / 凭据 / 真值 / 越权范围 | 改远端数据、要密钥、定口径、动他人资产 |
| `不可逆` | 不可逆且无默认解 | 删数据、force push、对外发布 |
| `用户要求二选一` | 用户主动问「A 还是 B」 | — |

**发现的缺陷默认修**：自己发现的问题（含本 skill 自身缺陷）能改就改，不转成「建议」；改不了才报，并给阻塞原因与影响面。

**拿不准时取可逆的一半**：不确定是否越权，先做可逆部分，把不可逆部分留到能判定的那一轮。动作**不可拆分**时按准入第 2 条判；**不得以「拆不动」为由整体停摆**，也不得把不可拆的动作说成可拆。

**汇报双轨**：

| 轨道 | 内容 |
|---|---|
| 聊天 | ①结果（数字/状态）②自主延伸清单（用户没要求但做了的，一行一条）③待裁决项（须过复命闸，≤3） |
| 详细交付文档 | 完整探索树（根＝用户原话；一层＝拆出的方向；叶＝决策＋证据＋产物） |

**探索树**（落交付文档；聊天只给根＋一层）：

```
根：<用户原话>
├ 判断：<判型 / 怎么理解的>
├ 方向1 <做什么> → 证据 <命令 | 路径:行号> → 产物 <文件>
├ 方向2 …
└ 自主延伸：<用户未要求但明显该做的>
```

**自主延伸是成果，必须显式成列**——否则用户只看到「照做了」。

**复命清单模板**（落 `<ws>/.ctbz-record/<slug>/复命.md`，由 `内审.mjs 复命` 校验）：

```
# 复命 <slug>

自主延伸:
- <做了什么> → <产物路径>
（无则写 `无`）

自主修复:
- <自己发现并已修的缺陷> → <产物路径>
（无则写 `无`）

待裁决:
- <事项> | 准入: 四扇门
（无则写 `无`）
```

三段均为必填；「待裁决」每条必须带 `准入: 四扇门｜不可逆｜用户要求二选一`。**整行**出现本 skill 特征串（`SKILL.md`／`skills/ctbz`／`references/`／`本 skill`／`发布链`）即判不合格——那说明 skill 里已有指令，该去做而不是来问。
```

### 2.3 `scripts/内审.mjs` 新增 `复命` 子命令（机械闸）

```
node <skill>/scripts/内审.mjs 复命 --file <复命.md> [--json]
```

| 退出码 | 条件 |
|---:|---|
| 0 | 通过 |
| 1 | 校验不通过（逐条列违规） |
| 2 | 用法错误（缺 `--file`、文件不存在、无法读取） |

校验规则（G1–G6，全部通过才退出 0）：

**段边界定义**：段标题＝行首（零缩进）恰为 `自主延伸:` / `自主修复:` / `待裁决:` 的行；段内容＝该行之后至下一个段标题或文件末尾之间的**非空**行。冒号全半角等价，字段名两侧空白忽略。

| # | 规则 | 不合格条件 |
|---|---|---|
| G1 | 三个段标题齐全 | 缺任一段（含只写 `无` 但缺段标题） |
| G2 | 每段的非空行要么以 `- ` 开头，要么整段恰为 `无` | 出现其它形态的行 |
| G3 | 「待裁决」段非 `无` 时，每条必须含 `准入:`；取值＝`准入:` 之后到行尾之间的 `trim()` 结果，必须**逐字等于** `四扇门` / `不可逆` / `用户要求二选一` 三者之一 | 缺 `准入:` 或取值不等 |
| G4 | 逐行先归一化（`toLowerCase()`、全角转半角、去所有空白），再匹配本 skill 特征串：`skill.md`、`skills/ctbz`、`references/`、`本skill`、`发布链`、`命令集`。**不限字段、不豁免** | 命中即不合格（= 明明有指令却来问） |
| G5 | 逐行归一化后匹配 `建议`、`待修`、`遗留`、`已知缺陷`、`未修`、`只报不改`、`下次再修` | 命中即不合格（可修缺陷须进 `自主修复`，对应实例 E2/E3） |
| G6 | `自主延伸` / `自主修复` 段非空且非 `无` 时，每条须含 ` → ` 分隔的产物路径 | 缺产物路径 → 不合格 |

- `--json`：stdout 单行 `{"ok":true,"mode":"复命"}` 或 `{"ok":false,"errors":["<行号>: <原因>"]}`。
- 人读模式：`✓ 复命闸通过` 或逐条 `✗ <行号>: <原因>`。
- 与既有 `init` / `check` / `link` 共用 `--json` 语义与退出码分层；不写任何文件；零网络。

## 8 已声明的已知限制（不构成阻塞，写进 CHANGELOG 与 SKILL.md）

| # | 限制 | 理由 |
|---|---|---|
| K1 | 复命闸是**启发式文字闸**，不穷尽绕过路径（如用同义词「本条协议」「规则文件」指代本 skill，或把特征串拆到两行） | 文字闸的价值是提高成本、暴露模式，不是形式化证明；穷举同义词不可判定 |

| K3 | `自主修复` 段的产物路径不做存在性校验（只查 ` → ` 形状） | 存在性校验会让闸门依赖仓库状态，误伤临时产物路径 |

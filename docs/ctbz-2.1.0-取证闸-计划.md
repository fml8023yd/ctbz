### 3.1 `派发闸.mjs`：`--level l1` 增「取证校验」一节

**新增常量**（与 `LEVELS` 同级，`派发闸.mjs:50` 之后）：

```js
const EVIDENCE_DIR = "docs/取证";
const NUM_CLAIM_RE = /(?<![.\d])\d+\s*(?:处|个|席|条|份|行|次|轮|项|类|点|步|版|倍|阵营)|(?<![\u4e00-\u9fff])[〇零一二三四五六七八九十百千万两]+\s*(?:处|个|席|条|份|行|次|轮|阵营)/g;
// 序数过滤：命中前紧邻「第」或「第 」的丢弃（如「第 3 处」不是数量断言）
const FILE_LINE_RE = /[A-Za-z0-9_./\u4e00-\u9fff-]+\.(?:mjs|js|sh|md|json|yaml|yml|ts)[:：](\d+)(?:\s*[-–]\s*(\d+))?/g;
const CN_DIGIT = { "〇":0,"零":0,"一":1,"二":2,"两":2,"三":3,"四":4,"五":5,"六":6,"七":7,"八":8,"九":9 };
```

`cnToNum(s)`：按 `十/百/千/万` 折算中文数字串为阿拉伯数字（`三十五` → `35`）；折算失败按原文串比对。

**新增函数** `evidenceProblems(planText, ws)`（**两参**；E1 读计划正文声明的路径，不再需要 slug）：

| # | 规则 | 不合格条件 |
|---|---|---|
| E1 | 计划正文含 `取证文件: <相对 <ws> 的路径>`（剥反引号）；该文件存在、非空，且 `resolve(ws, p)` 落在 `<ws>/docs/取证/` 之下 | 缺行 → `✗ <plan>: 缺 取证文件: 行`；缺文件/空/越界 → `✗ 缺取证文件 <p>；生成：mkdir -p <ws>/docs/取证 && { echo '# 取证原文（<slug>）'; 把 §2 的 grep/wc/node 输出原样粘入; } > <ws>/<p>` |
| E2 | 计划正文中每个 `文件:行号` 必须真实（ref 串含空白视为误提取，丢弃不判）。**解析顺序**（命中即止）：`<ws>/<p>` → `<ws>/skills/ctbz/scripts/<p>` → `<ws>/skills/ctbz/<p>` → `<ws>/tests/<p>`。**范围写法** `file:a-b` 拆为 `file:a`、`file:b` 各自独立校验（不写 `file:a-b-c` 连写）。命中后校验 行号 ≤ 该文件 `wc -l` | 任一不满足 → 逐条列 `✗ 计划:行N 「<ref>」不可达（或找不到文件）` |
| E3 | 计划正文中每个数量断言（`NUM_CLAIM_RE`）**所在行必须含 `↗`**（行内任一位置即可） | 缺 → `✗ 计划:行N 「<claim>」未标取证锚点（同行加 ↗ #<锚点>）` |
| E4 | 带 `↗` 的数量断言，其**裸数字**（阿拉伯原样；中文串经 `cnToNum` 折算后）必须出现在取证文件正文中。**词边界** `(?<![0-9.])<n>(?![0-9.])`；折算失败按原文串比对 | 未出现 → `✗ 计划:行N 「<claim>」在取证文件找不到数字 <n>` |
| E5 | 计划正文含匹配 `/^#{2,3}\s.*现场核对/m` 的小节标题 | 缺 → `✗ 缺「现场核对」小节` |
| E6 | 计划正文**无任何** `文件:行号` 与数量断言时，E2–E4 自动通过；E1、E5 仍必查 | — |

**抽取范围**（逐行判定，命中任一即跳过该行）：**标题行 `/^#{1,6}\s/`**｜``` 围栏内的行｜表格分隔行 `^\|[\s\-:|]+\|$`｜反引号包裹的片段（剥掉后再扫）｜含 `.ctbz-record/取证/` 或匹配 `/^\s*取证文件\s*[:：]/` 的行｜位于 `^#{2,3}\s.*(验收|不做|非目标)` 及其之后小节的行（`不做`/`非目标` 节整节跳过）。
**表格数据行的处理**：以 `|` 分列后，**E2 对全部列跑**；**E3 判整行是否含 `↗`**；**E4 校验该行所有列中每个数量断言的数字**（断言列与依据列都查）。
**整行豁免**：行内含 `↗` 时 E3 通过，但 **E2 与 E4 仍跑**（标了锚点不等于数字有出处）。
**中文数字**：`NUM_CLAIM_RE` 覆盖中文数字；折算失败按原文比对。示例：**拆行**（数字与量词被换行分隔）不在机械闸面，由反审人工兜底。

```text
中文数字命中示例（fenced，不入闸面）：三十五处 → 折算 35
拆行示例（不入闸面）：共
35 处
```
**接入点**（行号级，逐字）：在 `派发闸.mjs:348-350` 的免审依据检查之后、`:352` 的 `scanReceipts` 之前插入：


`:358` 的 `if (level === "l1" && scale === "免审")` 短路分支**保持不动**——因 `missing` 已在 `:352` 之前填充，免审计划同样吃到 E1–E6；`checkFailed` 在 `:359` 自然生效。
**唯一调用点**：`runReviewLevel` 是单函数，l1/l2/l3 共用 `:350` 之后同一插入点 —— **全仓仅此一处调用**；l2/l3 的差异只在 `:339` 的 `dir` 三元，不另加行。`--task` 夹具计划与 l1 同校（`missing` 非空即拦截，`:358` 分支无需改动）。
**review 块**：`pass()` 的 payload 增 `evidence: <计划正文声明的取证文件相对路径>`（l1/l2/l3 均带）。
**豁免与影响面**：`review_scale: 免审` 的计划同样适用 E1–E5；**历史计划不重跑**，不受影响；`--json` 与人读输出沿用既有 `missing` 渲染，不新增格式。

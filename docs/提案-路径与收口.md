## 二、根因（一句话）

**我的「完成」判据是内部判据，不是外部判据。**

| 表现 | 内部判据 | 外部判据（应有） |
|---|---|---|
| 随便找路 | 我用了我想到的入口 | 这条活有没有已知的最优入口？ |
| 探索了一下 | 我觉得找齐了 | 找齐的判据是什么、能不能重跑？ |
| 交差不管 | 我交付了 | 别人接得上吗？下次谁再碰它？ |

**现有机制全在加厚「交付那一刻」**（反审三层、复命闸、自证自疑），**没有一条管「路径选择」与「交付之后」**——所以这三件事至今无闸。

## 三、三条机械修法

| 对应 | 修法 | 机械载体 |
|---|---|---|
| A | **路径留痕**：开工时写「选了哪条路 + 为什么不走另外 ≥1 条」；收尾对照实际走了哪条 | 复命清单增 `路由:` 段（≥2 条候选，各含「为何不走」）；与 D-10 合并 |
| B | **穷尽判据前置**：任何「找齐 / 改完 / 全部同步」结论，必须先写判据（全仓 `grep` 命令 + 反向断言 + 排除项），否则不许用「全部」二字 | `复命` 闸增 **G10**：文本含 `全部｜所有｜无遗漏｜彻底｜一处不漏` 且同段无 `grep`／`--exclude`／反向断言 → 不合格 |
| C | **交付即认领**：交付物必带「后续谁在什么条件下会再碰到它 + 再碰到时第一动作」 | 复命清单增 `续作:` 段（≥1 条） |

**为什么这三条能拦住**：A 让「随机路径」变成可审的选择（有对照物才能说你选错了）；B 让「我觉得找齐了」变成可重跑的判据（本会话 35 处的账就是这么欠下的）；C 让「交差」变成「交接」。

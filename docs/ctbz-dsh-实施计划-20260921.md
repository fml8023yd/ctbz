## 1. 背景（给新鲜执行者/反审员）

### 1.1 ctbz 是什么
基于宿主 agent 系统的 skill 形态工作框架（装在 `~/.agents/skills/ctbz`）。核心为主会话协议：判型三问、四扇门（平台写/凭据/真值/越权）、反审分级（框架级 ≥3、完整 ≥4×双轮）、验收表（编号×状态×证据）、项目看板、知识库与自记。原宿主 ZCode（不可用），目标宿主 DeepSeek Harness（dsh）。

### 1.2 dsh 关键事实（均已实测取证）
| 事实 | 证据 |
|---|---|
| 技能根 `~/.agents/skills`（rank 500）/`<dshHome>/skills`(400)；目录包 `<name>/SKILL.md`；嵌套不发现；要求 `name` 匹配 `^[a-z0-9]+(?:-[a-z0-9]+)*$` | `dsh-skill-filesystem/README.md`、`dsh-skill/lib/index.js:17` |
| 无 agent profile 注册概念；角色落点＝subagent 工具实例（`persona`+`toolFilter`+`agentOptions`）或会话级 preset | `dsh-tool-subagent/README.zh.md:40-70` |
| `spawn` 后端支持全部启动期能力：`agentOptions`/`outputSchema`/`depthLimit`/`toolFilter`/`persona` | `dsh-subagent-spawn-in-process/lib/index.js` |
| `spawn_teammate` **不收角色与模型**；团队共享工作区、无独立工作目录、owner 不自动释放 | `dsh-experimental-agent-team/README.zh.md` |
| `workflow` 的 `agent(prompt,{provider,model,schema})` 可按调用点指定模型（本次实测跨 `deepseek-official` 与 `workbuddy` 双通道成功） | 本次实测 |
| workflow 结果上限 `maxResultChars 50000`，超限静默截断 | `dsh-tool-workflow/README.md` |
| 渠道：`deepseek-official`（仅 `deepseek-flash`/`deepseek-v4-pro`）；`workbuddy`（网关实有 42 模型，**baseURL 为 http 明文**） | 官方与网关实探、`~/.dsh/settings.yaml` |
| 凭据存于 `~/.dsh/.credentials.yaml`（0600）`refs.DEEPSEEK_API_KEY`/`refs.WORKBUDDY_API_KEY`；`apiKeyEnv` 声明在 settings | 本机实读 |
| `dsh-schedule` **不能无人值守**（需 live 根 agent、无 cron）；`~/.dsh/AGENTS.md` 当前不存在 | `dsh-schedule/README.zh.md`、`dsh-agent-instructions/README.zh.md` |

### 1.3 子进程模型名单（用户裁定）与取样规则
M1 `deepseek-official/deepseek-flash`（官方计费）｜M2 `workbuddy/glm-5.3-flash`（credit 0.01）｜M3 `workbuddy/hy4-preview-f`（0）｜M4 `workbuddy/hy3`（0）｜M5 `workbuddy/kimi-k2.8-preview`（0.1）
**讨论/反审/动脑 → 4 家提供商每家至少 1 个；开发类 → 可排除 M5。** 反审席位用 M1 时取 `deepseek-v4-pro`（避免主进程自审同模型）。

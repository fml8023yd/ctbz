# ctbz-dash 迁移说明（main 线 ↔ dsh 线）

面向使用者的操作手册。配套差异见 `与main差异清单.md`。

- 两条线指向**同一个技能名** `ctbz`（装在 `~/.agents/skills/ctbz`），靠安装副本内容区分归属，二者**互斥**（同一安装目录只能有一份）。
- 主线（ZCode）`main`：在 ZCode 宿主跑，含 profile 注册链、`version: 2.0.3`。
- dsh 线（DeepSeek Harness）`ctbz-dsh`：在 dsh 宿主跑，注册链退役，`version: 2.0.5`。

---

## 1. 判定：当前安装副本属于哪个分支

读 **`~/.agents/skills/ctbz/SKILL.md` 首行 frontmatter 的 `version` 与第 7 行分支标识**：

```bash
head -8 ~/.agents/skills/ctbz/SKILL.md
```

| 识别信号 | 归属 |
|---|---|
| `version: 2.0.3` 且无「宿主/分支」标识行 | main 线（ZCode） |
| `version: 2.0.5` 且出现 `> 宿主：DeepSeek Harness（dsh）｜分支：ctbz-dsh` | dsh 线 |
| 用 `node <skill>/scripts/status --smoke` 返回 `{ok:true,mode:"dsh-status-smoke"}` | dsh 线 |

> 判定依据：`skills/ctbz/SKILL.md:3`（`version: 2.0.5`）、`:7`（分支标识行）。main 版同行无标识、version 为 `2.0.3`。

## 2. 从 main 线切到 dsh 线（部署命令）

工作区是唯一源，安装目录只被部署写入。dsh 分支的部署脚本与 main 同文件 `skills/ctbz/scripts/部署.js`，**请务必从 ctbz-dsh worktree 运行**（从 main 仓库运行会部署错误的源码）。

```bash
# ① 确保当前工作区是 ctbz-dsh 分支（不是 main）
cd /Users/maolong/Betty/草台班子/ctbz-dsh
git rev-parse --abbrev-ref HEAD   # 应回显 ctbz-dsh

# ② 部署前建议先备份当前安装副本（部署.js 会自动备份到 ~/Documents/.ctbz/manual-backups/<ts>-dsh/，
#    但手动多一层更稳）
cp -a ~/.agents/skills/ctbz ~/Documents/.ctbz/manual-backups/pre-dsh-$(date +%Y%m%d%H%M%S)

# ③ 运行部署（会 rsync 镜像 + 自动跑 发布检查.js 三步）
/usr/local/bin/node skills/ctbz/scripts/部署.js

# ④ 验证已切到 dsh 线
head -8 ~/.agents/skills/ctbz/SKILL.md   # 应见 version: 2.0.5 与 dsh 标识
/usr/local/bin/node ~/.agents/skills/ctbz/scripts/status --smoke
```

> 注意（已知风险，见 §4）：`部署.js` 在 dsh 分支**未改动**，其基线逻辑仍写 `~/Documents/.ctbz/部署基线.json`，未传分支专属 `--baseline`。双线互盖风险由「从正确 worktree 运行 + 部署前备份」兜底；不要在 main 仓库误跑部署。
>
> 发布检查第③步已切到 dsh 版 `status --smoke`（`scripts/发布检查.js` 内 `step("③ dsh 版 status 冒烟…")`），不再依赖 ZCode 的 `initialize status`。

## 3. 回退到 main 线

回退 = 移除 dsh worktree（不影响 main 仓库） + 用备份恢复安装副本。

```bash
# ① 移除 dsh worktree（仅删 worktree 目录，分支引用保留可再 checkout）
git worktree remove /Users/maolong/Betty/草台班子/ctbz-dsh

# ② 从备份恢复安装副本（取 ② 步或部署.js 自动生成的快照）
#    部署.js 自动备份目录：
ls ~/Documents/.ctbz/manual-backups/ | grep dsh   # 选最新 <ts>-dsh/
#    手动备份目录（若用过 ② 步）：
ls -dt ~/Documents/.ctbz/manual-backups/pre-dsh-* | head -1
#    恢复：
SNAP=$(ls -dt ~/Documents/.ctbz/manual-backups/*-dsh/ | head -1)
rm -rf ~/.agents/skills/ctbz
cp -a "$SNAP" ~/.agents/skills/ctbz

# ③ 若要从 main 仓库重新部署（确保是 main 工作区）
cd /Users/maolong/Betty/草台班子/ctbz   # 注意：不是 ctbz-dsh
git rev-parse --abbrev-ref HEAD           # 应回显 main
/usr/local/bin/node skills/ctbz/scripts/部署.js

# ④ 验证已回 main 线
head -8 ~/.agents/skills/ctbz/SKILL.md   # 应见 version: 2.0.3，无 dsh 标识
```

> 回退只动安装副本与 worktree，不改 `~/.zcode`（主线注册链数据原样保留）。dsh 分支的 worktree 目录删除后，分支引用仍在 `ctbz` 仓库，需要时可 `git worktree add` 重建。

## 4. 遗留项（如实列出，不粉饰）

1. **`~/.zcode` 下仍有 106 个 ZCode profile 未清理**（`ls ~/.zcode/agents | wc -l` → 106）。本阶段非目标不动；主线（ZCode）仍依赖这些 profile，清理会破坏 main 线，故保留。
2. **`~/.dsh/AGENTS.md` 尚未创建**（dsh 计划的 agent 指令落地文件缺失，`dsh-agent-instructions` 已声明需此文件）。当前 dsh 派发靠 `SKILL.md` + persona 文本兜底。
3. **dashboard / 看板引擎本阶段未改动**（仅 `references/项目看板.md`、`dashboard-workflow.md` 去 ZCode 措辞；`scripts/dashboard/` 引擎沿用 main）。
4. **子 agent 无 `toolFilter` 的只读约束缺口**：`workflow.agent()` 只消费 `provider`/`model`，`toolFilter` 静默丢弃，只读约束靠 prompt 声明（见 `references/派发.md §1`）。`subagent` 实例虽有 `toolFilter` 字段，本阶段只出规格、未上线实例链路。
5. **workbuddy 走 http 明文**：`~/.dsh/settings.yaml:20` 的 `baseURL: http://101.133.151.121:18890/v1` 为明文 HTTP。探活仅发最小请求，不改用户网络配置；列为已知风险上报。
6. **`部署.js` 在 dsh 分支未改动**：基线文件仍为 `部署基线.json`（未传 `--baseline 部署基线-ctbz-dsh.json`），双线互盖风险靠「正确 worktree 运行 + 部署前备份」兜底，非隔离级防护。
7. **差异全部为工作区未提交改动**：HEAD 与 main 同 commit `3361bb0`，本文档（T8）与全部 T2–T9 成果均未 commit（受硬约束「不 git commit」限制）。

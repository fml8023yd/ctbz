## 三、根因（三条，均有证据）

| # | 根因 | 证据 |
|---|---|---|
| R1 | **触发词是自我封闭的索引**：条目与触发词都由 AI 写 → 索引的是 AI 的措辞，不是用户的措辞 | `BTY-KNOW-4010` 触发词＝`五件套｜交付包｜特征衍生交付`；`BTY-KNOW-7000`＝`上线与打分｜模型注册｜模型打分｜…`。**都没有**「特征开发」「模型上线」 |
| R2 | **强制注入层只管「怎么说」**：`AGENTS.md` 58 行全是输出规约（起手式 / 末段契约 / 哑巴模式），内容路由为零 | 结果：格式每次都像 ctbz，路线不一定对 |
| R3 | **没有路由表，也没有路径记忆**：5 个入口（知识库 `目录.md` / `references/` / `docs/` / `.ctbz-record/` / `git log`）互不知道；同类问题每次重新找，**走通的路径不沉淀** | 本会话前 3 个版本（2.0.6–2.0.8）全程未调用 `知识库.js`，直到用户提示「如果你有知识库」 |

## 四、三个选项

| 选项 | 内容 | 代价 | 判断 |
|---|---|---|---|
| A 最小 | `SKILL.md` 顶部加「开口三问」：①这是哪类活 ②知识库对应分区查过吗 ③本项目有无 `.ctbz-record` 续作 | 低 | 强制注入＝一定执行，但仍是 prose |
| B **推荐** | A + **一张全局路由表**（活类型 → 先读哪个分区 → 再读什么）+ 收尾把走通的路径写进知识库 `常用.md` | 中 | 路由表是唯一入口；路径记忆让同类问题越走越快 |
| C 重 | B + 检索加权（触发词别名槽自动回填 + `常用.md` 置顶 + 命中排序出「最该读的 3 条」） | 高 | 需要动 `知识库.js`，且排序权重容易失真 |
